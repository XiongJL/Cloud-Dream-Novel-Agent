# 章节篇幅、生成额度与失败恢复（2026-09-09）

## 产品设置

- 完整章节默认 **2300 字**，允许约 ±10%（2070—2530）的浮动；续写一段默认 500 字。
- 作品设置新增“整章默认目标字数”。本次明确字数要求优先，其次是本次表单参数、作品设置、产品默认值。支持 `1800—2200 字`、`两千三百字`、`2.3千字` 等表达。
- 字数和模型输出 Token 分离。中文篇幅校验按 Unicode 汉字计数，不计标点、空白、数字和拉丁字母；英文按空白分词。编辑器原有字数统计口径未统一，界面统计可能与篇幅校验不同。
- 空白章节打开 AI 续写时使用作品整章默认；已有正文打开时默认续写 500 字。新章提示词明确要求完整开场、冲突推进和章末收束或悬念。
- 作品参数使用已有 `Novel.formatting` JSON 的 `writing.chapterTargetLength` 字段保存；更新时保留其他格式和未知字段，无需数据库迁移。

## 自动生成额度

新用户默认“自动分配（推荐）”；旧配置缺少模式字段时仍按手动配置解释，不静默提高已有额度。普通界面显示生成额度模式和只读上下文上限；手动输出限制及上下文覆盖放入“高级：接口资源限制”。

| 任务 | 首次输出额度 | 发生可安全重试的截断后，最多一次 |
| --- | ---: | ---: |
| 标题 | 1024 | 2048 |
| 意图 / 规划 | 4096 | 8192 |
| 正文 | **18432（18 × 1024）** | 32768 |
| 编辑审校 | 8192 | 16384 |
| 创作素材 | 8192 | 最多 16384 |

这些是请求上限，不是实际扣费量或期望章节字数。模型的思考内容可能消耗输出额度。手动模式不自动增额；单次请求还受模型已知能力、上下文余量和产品 32768 Token 上限限制。

模型输出能力与上下文容量分别处理，不再用上下文容量的固定比例推算输出能力。当前只对明确识别的 DeepSeek V4 flash/pro 使用输出能力档案；其他模型标记未知。产品安全上限单独记录，不伪装成模型规格。模型档案依据见 `shared/modelOutputCapabilities.ts`；接入新模型时需维护已验证的能力信息。

装配上下文时为一次截断恢复预留空间。正文完成后实测篇幅：偏离目标且剩余时间允许时，最多发起一次篇幅调整，不嵌套增额重试，共享正文阶段原有超时。若调整失败，保留已经完成的原稿并提示“篇幅待审核”；不会无限补写。生成元数据记录目标范围、实测值、是否达标、是否尝试调整、请求次数及阶段输出额度上限。该上限不等同于整项 Agent 任务的实际总用量。

审校后的重写沿用原稿篇幅范围；只有新的审批意见明确调整字数时才覆盖。复用 preparedContext 时仍读取当前作品默认设置，避免旧上下文带回旧的 500 字目标。

真实审校复测发现：原 3 分钟共享时限不足以同时容纳 8K 首次尝试和 16K 恢复，已调整为共享 5 分钟，Automation/工具传输层分别为 330/360 秒，整项 Run 仍受自身截止时间约束。Python 重试分类优先尊重下层明确的 `retryable=false`，防止额度恢复已耗尽后又因错误码属于超时而重复整轮请求。

## 审校失败恢复

正文保存后，若编辑审校发生输出截断或可识别的接口错误，运行保留可审核草稿并提供“重试审校”。恢复记录持久化失败节点和源草稿 ID、版本；重启后从失败审校继续，不再生成一遍正文。已修改或不可审核的源草稿会被拒绝，避免对过期版本继续审校。

此变更针对生成后审校阶段。历史 `recovery=null` 的失败运行没有回填恢复描述；首次正文生成尚未产生完整草稿的超时，也不能冒充“正文已保存”。
