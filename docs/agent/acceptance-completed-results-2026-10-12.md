# 已完成分析结果收尾：实现与验收

日期：2026-10-12

## 用户行为

失败的只读分析任务有可复用结果时，显示“仅用已完成结果收尾”。原会话也识别“就以当前结果提炼，后续章节可以不用管了”等明确指令，走 `retry_failed_run / use_completed_results`，不另建整本分析计划。

首版支持内置文风提炼，以及明确启用章节分析的自定义 Skill 在编辑审核、改写规划、世界观一致性链路中的分析阶段。运行中、取消中、已取消、写入阶段和未知真实副作用不进入此路径。没有可用结果、只讨论不执行、待审批或待澄清时返回原因，不误启动新任务。

原 run 保留失败记录，创建关联的收尾 run，沿用同一 plan、step、锁定的 Skill 版本和原检查点。用户调整的是当前任务的分析范围；原计划后续步骤及原 Skill 的编写、校验和审核链路继续执行。产物依然经过既有用户审核入口，不自动安装 Skill 或写回小说正文。

## LangGraph 与范围冻结

1. 按原根 run + step 的 owner 读取已完成、已核验的分析叶子；用子图检查点确认整个章节 job 已完成。长章节只有部分分片完成时，整章排除。
2. 不混用多个来源/方法图。存在多个候选图时，以失败节点或最后章节/汇总进度的 unit ID 确认原图；不能确定时停止收尾。
3. 冻结章节集合、未分析章节集合、来源 graph key、叶子 ref 和结果 hash；manifest hash 写入父图检查点。晚到的原任务响应不扩大冻结范围。
4. 收尾前通过 `representation=catalog` 核对选中章节的版本与更新时间。目录的存储文档 hash 和提取正文/编辑器缓冲区 hash 不是同一种表示，不能相等比较；正文快照 hash 保留在原叶子证据中，冻结 manifest 另行核验结果 hash。
5. 子图只派发汇总节点，不调用正文读取、章节分析或全书执行规划。保持原 owner 的总调用/Token 预算；显式收尾不绕过配额。
6. 收尾模型请求使用独立的 closure namespace。被用户排除的原分析请求不阻塞新汇总；收尾自身的未知请求仍需结果核对，不可重复收费请求。原 run 恢复行为不变。
7. 收尾失败再次重试时沿用原 manifest 和结果集合；不会重新扫描、自动扩大章节范围。

## 专家与交付

通用专家输入只保留冻结范围的章节、证据和候选；逐页审核保留全部候选，不以根摘要替代完整候选。移除旧范围批次和范围外章节/全书叙事摘要，保留既有项目设定资料。

文风编写链路使用已有核验分析生成成员正文、校验/修复并编译 Skill Pack。最终草稿及报告标注实际 `N/T`、跳过数量、未分析章节标题，保存 manifest 供追溯。报告不可声称完成全书分析。收尾成功的 run 为 `completed`；原范围有跳过章节时 `completionKind=partial`。

## 验证

- `test_completed_results.py`：聊天指令、不可用/执行受阻时不重规划、目录与正文 hash 不同、冻结后晚到结果不扩大范围、缓存复用、manifest 篡改、未完成长章节、多方法图隔离、来源改版在模型调用前拦截、33 个专家候选全部进入审核且范围外材料移除。
- `test_agent_skills.py`：HTTP/FastMCP 两种工具通道，三章中第三章失败；截图原句触发关联收尾；不重复三次正文分析；只核对选中的两章目录；继续成员编写/校验/编译/报告，两个成员可供审核，最终标注 `2/3` 和遗漏章节。
- 相关回归包含章节图、重启恢复、通用专家分页、自定义 Skill、系统错误与取消路径。
- Renderer/Electron 类型检查及恢复按钮、终态展示、报告交付、结构化输出、自适应来源、系统错误、会话时间线专项检查。
- Python 全量回归：433 passed（287.21 秒）；最后的目录/正文 hash 修正后，收尾 12 项与独立 500 章图复测共 13 passed。两套回归同时进行时，额外 500 章压力复测曾遇到一次 SQLite busy；停止重叠压力后独立复跑通过。该失败按既有系统错误路径终止，没有吞掉或误报成功；不能据此宣称所有磁盘压力下均无锁冲突。
- Renderer/Electron `tsc --noEmit` 均通过；七组 Node 专项检查均通过。HTTP/FastMCP 完整文风链路十个场景通过。
