# 草稿箱与文风包标签方案

状态：产品方案，尚未实施。日期：2026-10-14。

## 1. 目标与现状

目标是让生成结果归属于小说，讨论历史归属于会话。删除会话后，待审核草稿仍有稳定入口，能够继续审核、调整和写回。

当前删除会话只清理 AgentConversation、AgentMessage、AgentRun、AgentRunEvent 和 AgentArtifact。DraftSession、DraftBatch、AgentSkillDraft 独立保存；问题主要是 UI 从会话中的 run/artifact 引用打开草稿，删除引用后缺少入口。已有 draft.list、draft.batch.list、agent_skill.draft.list 等读取能力可复用，但列表不能一次返回全部正文。

## 2. 页面入口

结合现有「素材生成」页面，优先复用 AI 创作工坊与右侧草稿区作为统一草稿工作台。在创作工坊顶部增加「草稿箱」标签：素材生成／小说问答／草稿箱。Agent 左侧「待改清单」下提供「草稿箱」快捷入口，指向同一草稿列表和详情。待改清单继续记录修改建议。

默认范围为当前小说。侧栏数字只统计可审核的独立草稿条目，多章批次计一项，避免把父批次和各子章重复计数。

```text
AI 创作工坊
  [素材生成] [小说问答] [草稿箱]
  草稿箱：待审核／需处理／处理中／历史
  当前小说的草稿列表 → 右侧类型对应的审核面板

Agent 创作
  待改清单       3
  草稿箱         2
  ──────────────
  会话列表
```

草稿箱主体提供「待审核」「需处理」「处理中」「历史」四个状态视图，并按章节/多章批次/创作素材/Skill 过滤。可搜索标题、按最近更新排序；侧栏徽标对应待审核数量，需处理数量在视图标签中单列。

示例条目：

```text
[多章草稿] 第三章 · 三点四十分的取件人
1 章 · 待审核 · 10 分钟前
来源：开启新一章内容（会话已删除）
                         [打开审核] [⋯]
```

点「打开审核」后，复用现有章节/批次/素材/Skill 审核面板。可以保留草稿列表并在右侧打开；窄屏复用已有抽屉布局，提供返回草稿箱。页面不依赖 activeConversation 或必须选中一个已有章节才能加载，也不自动创建空会话。

### 现有素材页面的复用边界

已核对：AIWorkbenchShell 提供现有工坊外壳；AIWorkbenchDraftDock 提供素材的分类、勾选和编辑；EditorWorkspace 已有宽屏侧栏与窄屏抽屉；素材的保存/确认经 draft.update、draft.commit。Agent 素材草稿也保存到 ai-workbench 工作区，可以基于同一持久化对象统一。

useCreativeDraftSync 当前用 draft.get_active 按小说及 ai-workbench 工作区加载最新活跃草稿，并每 2.5 秒刷新。它是当前素材编辑器的同步机制，尚不是多类型、可选历史草稿的管理器。统一后按明确的类型和草稿 ID 读取，不把其他类型的 payload 强制转换为 CreativeAssetsDraft，也不让周期刷新将用户正在审核的历史草稿切换回最新草稿。

素材编辑器与 Agent 素材审核共享基础字段编辑能力，保留 Agent 的意见、版本和写回校验。章节复用差异/全文/批次审核组件；写作 Skill 复用 SkillDraftReviewCard。素材里的「技能」是小说能力设定，与写作方法 Skill 分开。

顶部「草稿」按钮继续作为右侧草稿区的开关，面板头部补充当前草稿标题、状态和「全部草稿／切换草稿」。徽标统一统计待审核草稿包数；详情显示该包包含的素材条目数或章节数。当前徽标统计素材条目且遗漏 worldSettings，不能直接当作待审核草稿数量。

统一素材字段同步时必须保留全部分类：当前 useCreativeDraftSync 的 payload 投影也遗漏 worldSettings。纳入素材保存/恢复专项验证，避免在复用时继续漏显示或漏保存世界设定。切换草稿先保存或提示处理未保存编辑；已排队提交必须绑定原草稿 ID 和版本，不能转而写入后来选中的草稿。

## 3. 归集与状态规则

| 类型 | 草稿箱条目 | 打开后的行为 |
| --- | --- | --- |
| 单章草稿 | 独立 DraftSession | 差异、正文编辑、审批意见、保存、确认写回 |
| 多章批次 | 一个 DraftBatch | 展开子章，显示已生成/总数与已提交前缀，沿用现有批次审核 |
| 创作素材 | 一个素材 DraftSession | 沿用素材选择、验证与写回流程 |
| Skill / Pack | 一个 AgentSkillDraft | 查看成员、验证结果和可见范围，通过审核后保存发布 |

批次子草稿不再作为独立条目重复显示。历史遗留的孤立子草稿保留独立入口，并标记批次信息缺失，不能伪造父批次或批量写回能力。

「需处理」包含来源版本失效、未完成批次、待修复 Skill 草稿等；「处理中」只能来自可查询的运行/Operation 状态，不能仅凭旧字段推断任务仍在执行。「历史」包括已写回、已发布、已丢弃条目。已丢弃结果先只读查看；首版不假装现有 API 已支持恢复丢弃状态。

Skill 草稿按创建时关联的小说归集。设置所有小说可见表示发布后的可见性，不让未发布草稿在所有小说的草稿箱重复出现。无小说来源的历史全局 Skill 草稿单独标明来源缺失，并通过明确的全局筛选访问。

## 4. 删除、调整与来源

### 删除会话

有待审核草稿时，确认文案为：

> 删除会话将清除聊天和运行记录。此会话生成的 1 个待审核草稿会保留，可从「草稿箱」继续处理。

按钮为「取消」「删除会话，保留草稿」。首版不加入默认勾选的联合丢弃，也不在删除会话时暗中丢弃草稿。

会话存在执行中的任务时，前后端都阻止删除，并提示先停止任务、等待停止确认。避免任务继续回写已删除会话，或因会话删除导致结果状态不可见。

草稿的「丢弃」是独立操作。多章批次提示影响的未提交章节；已写回正文和已发布 Skill 不因丢弃而被删除。永久清理与自动过期不纳入首版，保留已有记录和备份策略。

### 继续调整

直接编辑、保存、审核、写回无需会话。只有点击「让 AI 调整」或发送审批意见时才需要会话：来源会话仍在，则允许继续该会话；来源已删除，则创建新的调整会话，明确关联 draftSessionId/draftBatchId/skillDraftId，并读取当前有效草稿和必要约束。

不恢复已删除聊天，不复制整段旧历史，不重新执行原生成流程。当前 Operation/来源快照不足时，说明具体缺失，不能显示一个实际不可恢复的「继续」按钮。新会话开始的任务仍遵守既有冻结版本和收费请求核对机制。

### 来源保存

保存精简来源信息：任务标题、创建时间、目标小说/章节、来源会话和 run 标识、冻结方法/包引用等。聊天内容不复制进来源快照。来源会话已删除时显示该状态；无来源的历史草稿仍可按其独立 ID 打开，不能因为无法关联会话而丢弃。

## 5. 接口与实施边界

- 增加 Main 侧元数据聚合列表接口，按小说、类型、状态分页返回；保留既有完整读取接口契约。列表只有标题、状态、数量、时间、来源摘要和独立 ID，点开时才读取正文与成员文档。
- 列表跨三类存储归集，遵守作用域；不要借此让 Python 直接访问小说业务数据库。
- 新 UI 用草稿 ID 定位并复用现有审核逻辑；所有写入继续校验版本、来源、未解决意见及批次顺序，不根据列表快照直接提交。
- 删除前校验与来源摘要保存、删除本身应通过一致的 Main 侧操作完成；避免 UI 先移除会话、后台删除失败却只写日志的现状。
- 以实际草稿记录作为状态依据。会话和草稿箱同时操作后刷新/通知；并发保存产生版本冲突时明确提示重新加载。
- 首次上线扫描现有草稿、批次和 Skill 草稿即可找回旧入口；不要求它们仍有 AgentArtifact。来源快照仅在可核实时回填，已丢失的会话名称显示「历史草稿／来源会话不可用」。

实施顺序：先草稿箱列表与独立打开审核，再补删除提示/后端保护/调整会话关联。两步完成后才允许将「删会话后可从草稿箱继续」写入正式产品文案。

验收覆盖：删会话后仍可打开并写回、重启找回历史草稿、旧孤立草稿、批次去重与前缀提交、已丢弃只读、来源失效拒绝写回、Skill 发布范围与版本冲突、会话/草稿箱并发操作、活动任务阻止删除、列表不携带全文。

## 6. 截图中的文风包版本与旧绑定

| 概念 | 当前显示/来源 | 含义 |
| --- | --- | --- |
| 文风包发布版本 | Composer 的 v1.0.0 来自 PackRevision.version | 这份已保存文风包的内容与组合版本，首个发布通常为 1.0.0 |
| 提炼器版本 | 内置 style-skill-extractor 1.4.0 | 生成工具的提示词、流程和验收版本，与产物版本分开 |
| 组合结构版本 | schemaVersion 1/2 | 保存与解析成员、任务绑定的数据格式，不表示模型或内容质量版本 |

更新提炼器不会自动改写已发布文风包。即使由 1.4.0 提炼器新建一个包，其首次发布也可以是 v1.0.0。

「旧版绑定」仅由 pack.schemaVersion === 1 触发。该结构按已保存的 Operation/Role 对应关系选择主/辅助成员；不同任务可能使用不同主成员。新版文风包结构明确一个语言核心，写作任务沿用该核心，按允许范围选最多一个辅助。两者都按包中的确定成员版本执行，不在运行时把旧组合偷偷换掉。

旧绑定不是报错或失效；确实不适用或不兼容的任务会由现有解析校验拦截。不过「旧版绑定」是实现术语，用户无法据此判断当前到底会使用哪些成员。

建议显示为「文风包：名称 · 包版本 1.0.0」，将橙色「旧版绑定」改为中性「按原组合运行」，在详情中展示各任务的主成员、辅助和版本。实际计划仍展示最终组合，不能在尚未确定任务时宣称本次一定使用某个成员。

后续可在 ⋯ 详情提供「调整文风组合」：预览现有组合和语言核心组合的差异，验证任务/角色兼容及所选主辅组合，生成新的 PackRevision 后供新任务选择；历史任务仍沿用冻结版本。此升级入口目前尚未实现。只升级组合不会修正文档内容或保证文风更自然；方法内容需要另走草稿修订和试写验收。
