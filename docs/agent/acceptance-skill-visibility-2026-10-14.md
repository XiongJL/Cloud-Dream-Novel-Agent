# Skill 可见范围：实施与验收

日期：2026-10-14。对应[设计方案](./skill-creation-visibility-design-2026-10-13.md)。

## 用户可见行为

- 新建单 Skill、文风 Pack 默认归属于当前小说；创建入口可主动选择所有小说可见。原文来源与保存范围独立。
- `/` 每行右侧 `⋯` 提供查看详情和范围设置；点击主体仍是本次使用。已选标签和已保存产物卡也可进入同一设置弹窗。
- 弹窗显示当前范围、归属小说、成员数量及修改影响，支持指定小说/所有小说。内置 Skill 范围只读；包成员转到包统一设置。
- 范围缩小先预览，再确认取消不适用的默认与绑定；扩大范围不自动设置任何小说默认。
- 普通切换保留原 ID、正文 Revision/Hash。共享成员需要明确选择隔离副本；同标识冲突提供另存独立副本，原对象和原引用保留。
- 新副本使用新身份并重算哈希，保留原版本和可核对的来源引用，不调用生成模型。范围设置没有加入模型工具权限。

## 程序边界

Native 在一个事务内复验范围配置版本、依赖及预览令牌，再处理包、成员和关联。依赖不仅包括当前 Pack，还包括启用默认锁定的旧 Pack Revision。没有把历史引用静默改成当前版本。

新增 schema v3 注册迁移，仅增加 Skill/Pack 的范围版本和草稿的发布设置字段。现有 Prisma 6.19.2 引擎未重新生成或替换；新字段用 raw SQL 读写，初始化 SQL 与 Prisma 源模型同步。

草稿最终发布设置有独立 CAS，生成中修改不更改内容版本、模型请求或检查点输入。提交时同步托管头并验证编译投影未改变；已通过的文风内容审核只在元数据重校验后继续使用，未通过的内容不能借范围修改发布。

未启动计划在新版执行链路重新检查范围；校验不完整也拒绝启动。已启动 Run 保存访问范围与精确成员快照，重试复制快照，正文仍按原版本加载。现有旧任务沿用原计划与精确版本读取行为，不在范围修改时批量重写。

当前选择注册表在刷新时清除不再可见对象；保存后刷新菜单，并更新已保存卡的当前范围。历史草稿头保留当时信息，当前范围来自已发布定义。

详情首版在同一轻量弹窗复用现有 Markdown 阅读组件；检查器里的已保存卡复用该弹窗入口。没有新增独立 Skill 管理页。源范围字段和默认设置语义保持原有定义。

新能力通过 `agent.skill.visibility` 与 preload 方法协商；新创建参数未设置时，Style 输入序列化不补字段，以保留旧检查点指纹。使用新功能需同时加载新版 Electron preload 与 Python Runtime。

## 验证

- Python 全量：**527 passed**，688.97 秒。仅已有 Starlette/httpx 测试客户端弃用提示。
- 新运行测试：结构化范围传递、旧输入序列化、执行前拒绝不适用/不完整范围校验、启动范围快照及原版方法消费、HTTP 元数据接口通过。
- Native 隔离 SQLite：跨小说列表、三种切换、成员原子同步、正文身份不变、过期影响预览、默认/绑定清理、共享成员隔离、旧版默认引用、单 Skill/Pack 同标识副本、草稿发布与来源保留通过。
- 既有 Skill Store 测试通过，并验证通过内容/试写验收的文风草稿可修改发布范围，原审核输入哈希留存，方法投影不变。
- 数据库生命周期：v2 → v3 保留原记录，初始化默认版本，重复升级幂等，旧迁移防篡改和失败回滚测试通过。
- 备份集成：41 个领域通过，包括旧备份、复制恢复、默认偏好、内容与引用保留、回滚和资源验证。新增范围字段沿用列发现及 ID 映射机制。
- Composer 与草稿审核回归、Renderer/Electron 类型检查、Prisma 源 Schema 校验通过。
- 实际生产 React 组件的隔离浏览器检查：`⋯` 不选择使用、详情正文显示、范围切换保存与菜单分组同步、取消不写入。使用次数保持 0；桥接器仅访问内存假数据。

## 使用

创建：`/` → 创建 Skill 或文风提炼入口 → 保存范围默认当前小说，可改所有小说 → 生成并审核保存。

后续修改：`/` → 目标 Skill/Pack 的 `⋯` → 设置可见范围 → 选择范围及归属 → 查看实际影响并保存。已保存卡的“设置可见范围”使用相同路径。

普通写作页直接 AI 操作未接入 Skill 选择，本功能也不增加全局默认调用。范围扩大后可在其他小说选择使用；之前因缩小范围取消的默认不会自动恢复。
