# Agent 章节读取范围与委托需求

版本：v0.1

日期：2026-07-29

状态：需求已确认，待实现

适用范围：聊天探索、结构化问答、计划生成、Run 执行、章节上下文装配、AI 推荐选项、活动记录和 Artifact coverage。

## 1. 背景

当前实现混淆了三件不同的事：用户希望处理哪些章节、允许 AI 读取哪些章节，以及 AI 实际读取了哪些章节。执行中的自由输入还可能只被拼入 `rag.ask.question`，没有转成真实章节 ID 和正文读取，导致用户明确输入“当前章 + 上一章”后仍只分析当前章。

本需求建立统一的章节读取授权和解析协议。核心目标不是给读取范围设置固定上限，而是确保每次扩展都有用户授权依据、真实章节来源、可验证正文覆盖和清晰的后续写入边界。

## 2. 已确认原则

1. **章节邻接按整本小说的全局顺序计算。** 卷是组织和展示结构，不是读取边界；上一卷卷尾与下一卷卷首必须连续。
2. **用户最新明确意见优先。** 同一请求或 Run 内，用户后提交的自定义答案覆盖 AI 选项、旧答案和默认范围；不得合并冲突选项，也不得静默回退。
3. **明确范围与读取委托分开。** “当前章 + 上一章”是确定性范围；“可以选择附近章节”是允许 AI 自适应选择上下文。
4. **读取范围不设语义硬上限。** 章节数量、卷边界和固定邻接窗口不得阻止获取完成任务所需的上下文；资源预算只控制分批、摘要、暂停和继续方式。
5. **只读会话可以形成修改计划。** 为保证计划可靠，可以继续扩展读取；计划只是只读产物，不构成草稿生成、章节修改或写回授权。
6. **读取权限不等于写入权限。** 作为上下文读取的章节不能自动成为改写目标。计划若建议修改这些章节，必须单独列为候选写入目标并在执行前确认。
7. **AI 选项必须真实可执行。** 范围选项必须绑定可解析的读取指令；内容建议选项必须基于已经读取且用户可查看的来源。
8. **不得以 RAG 代替明确正文读取。** `rag.ask`、向量 chunk 和章节摘要可以发现候选证据，但不能冒充对用户明确指定章节正文的阅读。

## 3. 范围模型

系统必须分别保存以下四类范围：

| 范围 | 含义 | 是否可由 AI 自行扩大 |
| --- | --- | --- |
| `targetScope` | 本次分析、审核或生成计划主要针对的章节 | 否，除非用户重新指定 |
| `readAuthorization` | 用户允许系统为完成任务读取的边界或委托策略 | 只能在用户授权语义内 |
| `resolvedReadScope` | Runtime 最终解析并实际准备读取的章节 ID | 可在委托策略内自适应变化 |
| `writeScope` | 后续草稿生成或写回允许影响的章节 | 否，必须单独确认 |

例子：

```text
用户：分析当前章，必要时可以选择附近章节，并给出修改计划。

targetScope          = 当前章
readAuthorization    = AI 可自适应选择相关章节
resolvedReadScope    = 当前章、上一卷卷尾、当前卷下一章
writeScope           = 空；计划可以提出候选，但尚未授权生成或写回
```

## 4. 全局章节顺序

1. 全局顺序按 `volume.order -> chapter.order` 排列，必要时使用稳定 ID 作为重复 order 的确定性兜底。
2. `上一章`、`下一章`、`前 N 章`、`后 N 章` 和连续区间都基于全局顺序，不在卷边界截断。
3. “当前卷第一章的上一章”应解析为上一卷最后一章；只有整本小说第一章才没有上一章。
4. 默认排除已删除章节；草稿、隐藏章节或特殊章节是否参与顺序必须由其业务状态明确决定，不能由标题猜测。
5. 范围解析结果保存 `orderFingerprint`。章节或卷被重排后，旧解析结果必须失效并重新解析，不能继续使用旧邻接关系。
6. 当前编辑器未保存内容仍只覆盖其对应 `chapterId`，不得用于替代其他章节正文。
7. “当前章”在任务创建或答案成功提交时必须冻结为具体 `anchorChapterId`。读取期间切换编辑器标签、跳转章节或改变当前选择，不得悄悄改变该任务的锚点；用户重新提交范围意见时才建立新锚点和新解析结果。

现有按卷调用的 `chapter.list(volumeId)` 不能单独承担全局邻接解析。Electron 工具层应提供小说级有序目录或专用范围解析能力；也可以由 `volume.list + chapter.list` 确定性组合，但 Runtime 不得让模型凭标题猜测跨卷邻接。

## 5. 用户意见优先级与生命周期

### 5.1 优先级

同一活动请求中的决策优先级固定为：

```text
用户最新成功提交的明确范围意见或自定义答案
> 用户最新选择的结构化选项
> Renderer 发起任务时携带的显式章节选择
> 用户此前在本次任务中的范围授权
> AI 推荐的范围选项
> 产品默认范围
```

- 明确的排除条件，例如“不要看后文”“只参考已经发表的章节”，优先于宽泛的“可以看附近章节”。
- AI 理解摘要、Planner 输出、Toolchain 元数据和模型推荐理由都不是用户授权来源。
- 自定义答案与预设选项互斥。提交自定义答案后，未选中的预设项必须从有效决策中消失。
- 自定义范围无法可靠解析时必须继续询问或展示解析失败；禁止默认成 `current_chapter`。

### 5.2 生命周期

- 读取委托默认只对当前请求、计划或 Run 有效，不自动变成后续会话的长期偏好。
- 同一 Run 中后续用户意见可以收紧、扩大或替换读取授权。
- 用户意见变化时，尚未完成且已越出新授权的读取应取消；基于旧范围生成的未发布选项、报告和计划必须失效。
- 已经展示或批准但尚未执行完的旧选项、报告和计划也必须标记为 `stale`，在新范围重新解析、补读和验证前不得继续产生副作用；保留旧版本只用于审计和对比。
- 已经完成的写入不因读取授权变化而自动回滚。后续修正必须进入新的计划、草稿与写回审核，不能把“用户最新意见优先”解释为静默撤销历史写入。
- 已经完成但不再属于新范围的读取可以保留审计记录，但不得继续进入模型上下文或 coverage 成功统计。
- 应用刷新、重启和 SSE 重连后必须恢复原始授权、解析结果、已读取来源和当前证据缺口。

## 6. 范围指令

### 6.1 明确范围

以下表达必须确定性解析，不交给模型自由决定：

- 当前章 + 上一章。
- 当前章 + 前两章。
- 第 3 章到第 5 章。
- 我选中的这些章节。
- 当前章和上一卷最后一章。

解析后必须得到真实、有序、去重的 `chapterIds`。任一目标不存在或不属于当前小说时整体失败，不允许部分成功后假装完整覆盖。

### 6.2 委托范围

以下表达代表只读选择权委托，而不是固定章节集合：

- 可以选择附近章节。
- 必要时多看一些上下文。
- 你判断还需要读哪些章节。
- 为了形成可靠计划，可以继续扩展阅读。

委托范围采用自适应读取：先从锚点和目录元数据出发，再根据证据缺口选择下一批章节。不得把“附近”预先固化为同卷或固定前后 N 章。

### 6.3 任务语义限制

- 读者盲测、无剧透检查等任务自身包含“不得读取未来章节”的语义限制。若用户要求同时读取未来章节，系统应询问是否切换为全信息编辑视角，而不是暗中破坏盲测。
- 用户明确要求只读历史章节时，自适应扩展只能向前。
- 外部资料、附件和后台设定仍遵守各自权限，不因章节读取委托自动开放。

## 7. 自适应读取流程

```text
用户任务或范围意见
  -> 解析 targetScope 与 readAuthorization
  -> 获取小说级全局章节顺序
  -> 解析明确范围，或生成第一批委托候选
  -> 读取真实正文 / 可验证章节上下文
  -> 计算 coverage 与 evidence gaps
  -> 证据不足：在授权内继续选择和读取
  -> 证据充分：生成分析、内容选项或修改计划
```

### 7.1 候选发现

- `chapter.list`、章节标题和新鲜摘要只能用于发现候选和判断读取顺序。
- AI 只能从 Runtime 提供的真实候选 ID 中选择，不能输出虚构章节 ID。
- 候选选择必须保存简短理由，例如“上一章包含当前冲突的直接铺垫”。

### 7.2 正文读取

- 明确多章范围必须通过一次权威 `chapter.scope_context.build` 覆盖全部章节，或对每章成功调用 `chapter.get`。
- 委托范围中，被用于具体内容判断的章节必须存在可查看的正文、摘录或带版本的上下文项，不能只有模型自报或无来源摘要。
- RAG 可以补充跨章线索；关键命中需要回到对应章节正文或可验证摘录。
- `contentModes='summary'` 只表示摘要覆盖，不能满足用户明确指定章节的正文读取，也不能单独支撑具体内容选项；除非用户明确接受摘要级部分结论，否则必须补读可查看的正文或带版本摘录。

### 7.3 证据充分性

停止扩展不能只由固定章节数量决定。至少满足：

- 用户明确指定的章节全部成功覆盖。
- 当前分析问题所引用的关键铺垫、冲突双方和承接关系都有来源。
- 模型没有仍会实质改变结论或计划的高优先级证据缺口。
- 最终结论、选项和计划只引用实际读取范围内的事实。

### 7.4 资源预算

- 单次模型窗口、工具并发、请求 deadline 和全文装配大小仍必须有工程预算。
- 预算用于决定分批、摘要、摘录、继续读取或暂停，不得被解释为用户只授权了固定 N 章。
- 达到当前批次预算但证据仍不足时，系统应继续下一批；达到任务 deadline 或不可恢复上限时，展示部分覆盖和缺口，并让用户继续读取或接受部分结论。
- 部分覆盖不得使用“完整分析”“已通读”或等价措辞。

## 8. AI 选项与可查看来源

### 8.1 范围或授权选项

范围选项可以在正文读取前出现，但必须满足：

- 每个选项绑定结构化 `scopeDirective`，而不只是标签和 Prompt 文本。
- 能在提交后解析为真实章节，或进入明确的自适应读取策略。
- UI 至少展示已解析的章节标题，或明确说明将自适应选择并在活动记录中展示实际章节。
- 选择后先完成相应正文读取，再继续分析或生成报告。
- 读取前的推荐理由只能说明速度、成本、授权和覆盖差异，不能声称基于尚未查看的正文。

### 8.2 内容判断选项

人物动机、伏笔处理、结构调整和修改方向等内容选项必须满足：

- 生成前通过 evidence gate。
- 每个选项的 `evidenceIds` 指向实际成功读取的章节或附件来源。
- 用户可以从选项或问题卡打开对应章节、摘录或来源详情；打开的是读取时的版本化证据，或明确标注当前正文已经变化。
- 推荐理由只能引用已读取事实，不得把未读章节当成依据。
- 如果不同选项需要不同的未读材料，先补读全部必需材料，或把当前问题降级为纯范围授权问题。
- evidence 因删除、权限变化或版本失配而无法查看时，对应内容选项不得继续作为可提交选择；Runtime 应重新读取或使问题组失效。

### 8.3 用户覆盖 AI 选项

用户选择“都不是”并输入新意见后：

1. 原 AI 选项不再是有效答案。
2. Runtime 解析用户原文中的范围、排除条件和目标变化。
3. 若范围变化，先重新解析和读取，旧 evidence gate 失效。
4. 新覆盖通过后才生成计划或恢复 Run。
5. AI 理解摘要只用于展示，不得改写或缩小用户原文。

### 8.4 问题组与证据时序

- 改变读取范围的授权问题，不能和依赖所选新范围正文的内容判断问题放在同一问题组，除非 Runtime 已经读取所有候选范围所需的共同证据。
- 常规流程是“提交范围答案 -> `scope_reading` -> evidence gate -> 生成后续内容问题或计划/恢复 Run”。范围读取不占用内容问题的 1–3 题名额。
- 若同组内容选项只对部分范围答案成立，Runtime 必须拒绝该问题组并要求模型拆分，不能让用户先选择一个尚不可验证的内容方向。
- 执行中固定一轮表示单个已展示问题组不动态追加题目，不禁止范围补读完成后在真正遇到新阻塞决策时创建新的 request。

## 9. 计划与写入边界

- 只读分析可以在上下文充分后直接产出修改计划。
- 计划必须分别展示“已读取上下文”“主要分析目标”和“建议修改章节”。
- 从上下文中发现的问题可以形成候选修改项，但相应章节不能自动进入草稿批次。
- 执行计划前，Runtime 根据用户批准的计划建立独立 `writeScope`。
- `writeScope` 增加、删除或重排章节时仍需要现有计划/章节拍审批和版本冲突检查。
- 用户只授权“可以读取附近章节”时，任何附近章节写入都必须 fail closed。

## 10. 数据协议

```ts
type AgentReadScopeDirective =
  | {
      mode: 'explicit';
      order: 'novel';
      anchorChapterId?: string;
      chapterIds: string[];
    }
  | {
      mode: 'relative';
      order: 'novel';
      anchorChapterId: string;
      before?: number;
      after?: number;
      includeAnchor: boolean;
    }
  | {
      mode: 'adaptive';
      order: 'novel';
      anchorChapterId: string;
      relation: 'nearby' | 'relevant_context';
      direction: 'past' | 'future' | 'both';
      constraints?: {
        excludedChapterIds?: string[];
        noFutureChapters?: boolean;
      };
    };

type AgentResolvedReadScope = {
  directive: AgentReadScopeDirective;
  authorizationSource: 'user_text' | 'structured_option' | 'renderer_selection';
  targetChapterIds: string[];
  contextChapterIds: string[];
  orderedChapterIds: string[];
  selectionReasons: Record<string, string>;
  orderFingerprint: string;
  resolvedAt: string;
  coverage: {
    requestedChapterIds: string[];
    completedChapterIds: string[];
    failedChapterIds: string[];
    contentModes: Record<string, 'full' | 'excerpt' | 'summary'>;
  };
};
```

协议约束：

- `AgentUserInputOption` 可以携带 `scopeDirective`；模型不能填写 `authorizationSource`。
- 用户选中范围选项后，Runtime 才将授权来源记为 `structured_option`。
- 自定义答案先保存原文，再由受约束解析器产生 directive；解析器输出不是新的用户授权，只是原文的可审计投影。
- `AgentUserInputResolution` 可以进入 `scope_reading`，完成解析和补读后才能进入 `plan_created` 或 `run_resumed`。
- resolved scope、工具观察、来源版本和 coverage 必须进入 Run/Artifact，而不是只保存在聊天文本中。

## 11. UI 与可观测性

- 问题卡区分“选择读取权限”和“根据内容选择方向”，不能使用相同推荐文案误导用户。
- 明确范围选项显示实际章节标题；跨卷时同时显示卷名，但不把卷作为边界。
- 自适应委托显示当前已选择、正在读取、已完成和仍缺少的章节。
- 活动流记录目录发现、范围解析、正文读取、RAG 补充和 evidence gate，不得只显示最终 `rag.ask`。
- 提交记录显示用户原始范围意见、解析后的实际章节和 AI 选择理由。
- 报告和计划显示实际 coverage；点击来源可以打开对应章节或摘录。正文已变化时优先展示读取时的版本化摘录，并同时提示最新版本，不能用最新正文冒充原 evidence。

## 12. 错误与并发

| 场景 | 行为 |
| --- | --- |
| 相对章节不存在 | 明确指出缺失关系；整本第一章没有上一章时不得伪造或静默忽略 |
| 跨卷目录读取失败 | 展示失败卷/章节并允许重试，不按当前卷截断 |
| 自定义范围有多种解释 | 提出一个聚焦澄清问题，不采用 AI 默认范围 |
| 用户在读取中修改范围 | 取消越界在途读取，使旧下游结果失效，然后按新意见继续 |
| 章节顺序或正文版本变化 | 使 resolved scope 或 evidence snapshot 过期并重新解析/读取 |
| 读取期间用户切换当前编辑章节 | 继续使用请求中冻结的 `anchorChapterId`；仅界面导航不改变范围 |
| 已展示或已批准计划依赖旧范围 | 标记为 `stale` 并在下一个副作用前暂停；保留审计版本，不自动回滚已完成写入 |
| 选项 evidence 已删除或不可查看 | 使对应问题组失效并重新读取或报错，不允许提交无可查看依据的内容选项 |
| 部分章节读取失败 | 显示部分 coverage；不得生成声称覆盖完整范围的内容选项或计划 |
| 自适应读取达到 deadline | 保存进度和证据缺口，允许继续；不得把资源耗尽解释为证据充分 |
| 读者盲测请求读取未来章节 | 询问是否切换任务语义，不暗中泄露未来内容 |

## 13. 验收场景

1. 当前卷第一章输入“当前章 + 上一章”，实际读取上一卷最后一章与当前章正文。
2. 整本第一章输入相同要求，返回明确的缺失关系，不回退成只读当前章后继续完整分析。
3. 用户输入“可以选择附近章节”，AI 可以跨卷选择相关上下文，活动流显示真实章节 ID、标题、读取结果和理由。
4. 自适应读取超过原先的前后 3 章仍可继续；系统通过分批和 coverage 管理资源，而不是拒绝合法上下文。
5. 用户在 AI 推荐“只看当前章”后自定义“当前章 + 上一章”，最终有效答案只包含用户原文，且正文读取先于 RAG 和报告。
6. AI 给出的范围选项均能解析和执行；内容建议选项均有可点击的真实 evidence。
7. 只读会话读取多个上下文章节并生成修改计划，但计划执行前 `writeScope` 仍为空或等待用户确认。
8. 用户随后只批准修改当前章，其他已读取章节不会生成草稿或写回。
9. 用户要求“不要看后文”后，后续自适应读取和模型上下文均不包含未来章节。
10. 章节重排后恢复旧 Run，系统检测 `orderFingerprint` 变化并重新解析邻接范围。
11. 任一必需章节读取失败时，不生成假装基于完整范围的推荐项、报告或计划。
12. 自动化断言顺序为：用户授权 -> 全局范围解析 -> 正文读取 -> evidence gate -> 内容选项/分析 -> 计划。
13. 用户提交“当前章 + 上一章”后切换到其他编辑器章节，Runtime 仍按提交时冻结的锚点读取；只有新的范围提交才改变锚点。
14. 一个问题组同时包含范围授权和依赖该范围的未读内容选项时校验失败；拆分后必须先完成 `scope_reading`，才能展示有真实来源的内容选项。
15. 用户在计划已展示或批准后收紧读取范围，旧计划立即变为 `stale` 且不能继续写入；已完成写入保留，修正通过新的审核流程完成。
16. 章节在问题卡展示后发生修改，来源入口能展示读取时的版本化证据或明确过期；若原证据不可查看，问题组失效而不是继续提交。

## 14. 实施拆分

### P0：正确性

- 全局章节顺序解析和 `orderFingerprint`。
- 明确/相对范围解析。
- 用户自定义答案覆盖默认选项，不再回退 `current_chapter`。
- 范围选项绑定 `scopeDirective`，选择后真实读取正文。
- 读取范围、目标范围和写入范围分离。
- 请求级 `anchorChapterId` 冻结，以及范围问题和证据依赖内容问题的分阶段校验。

### P1：自适应委托

- 委托读取策略、候选选择理由和迭代 evidence gate。
- 分批预算、部分 coverage、继续读取与恢复。
- 用户运行中修改授权时的取消和结果失效。
- 已展示/已批准下游产物的 `stale` 传播，以及版本化 evidence 的可查看性校验。

### P2：体验

- 章节来源可查看、跨卷标题展示和实际范围记录。
- 计划中的已读上下文/候选写入目标分栏。
- 范围解析、扩展次数、证据充分率和用户覆盖 AI 选项率诊断。
