# Agent 工作区连续性、后台运行与跨模式提醒需求

版本：v1.0<br>
日期：2026-07-30<br>
状态：已实现并通过验收<br>
适用范围：编辑器写作/Agent 模式切换、Agent 会话与输入草稿、后台 Run、结构化问答与审批断点、Agent 顶栏状态提醒、Renderer 性能。

## 1. 背景与问题定性

编辑器顶部的“写作 / Agent”在产品上是同一小说工作区内的视图切换，不应被解释为退出、重置或重新进入 Agent 工作区。

当前实现却将 `AgentWorkspace` 放在 `productMode === 'agent'` 的条件渲染分支中。切到写作模式时，整个 Agent Renderer 被卸载，带来以下问题：

1. Agent 输入框内容仅保存在组件本地 `input` state，重新进入后被重置为空。
2. 当前会话 ID、滚动位置和部分 Inspector 状态随组件卸载丢失或重新初始化。
3. Run 事件订阅在卸载清理中取消。任务虽然可能仍在 Runtime 后台运行，但 Renderer 无法继续投影新事件。
4. 如果后台任务在写作期间进入 `waiting_user_input` 或 `waiting_approval`，用户看不到提醒；返回 Agent 后还依赖重新加载和状态对账才能恢复表单。
5. 直接用 `display: none` 常驻完整 Agent 树也不是合格修复。写作编辑器每次更新都会改变 `content`，而 Agent 当前直接接收 `currentContent`；这会让隐藏的重型会话时间线参与 React 更新。

因此，本问题是模式切换语义、任务状态所有权和 Renderer 生命周期没有分层造成的需求级架构问题，不只是输入框的局部 Bug。

## 2. 已确认决策

1. **模式切换是无损视图切换。** 写作和 Agent 互相切换时，不销毁用户尚未提交的工作，也不停止正在运行的 Agent 任务。
2. **任务可以在写作模式后台继续。** 用户可以让 Agent 执行任务，同时在写作模式阅读或编辑其他章节。
3. **任务状态独立于 Agent 界面。** Run 订阅、状态投影、待回答问题和待审批检查点由稳定的会话/任务层持有，不能依赖当前是否展示 `AgentWorkspace`。
4. **Agent 界面采用优化保活。** 首次访问后可以保留必要的 Renderer 状态，但必须建立隔离边界，不能因写作正文每次按键而重渲染完整 Agent 树。
5. **阻塞事件必须可靠恢复。** `waiting_user_input`、`waiting_approval` 和章节拍确认等状态必须先持久化，再发通知；事件丢失、切换模式或 Renderer 重建都不能让确认入口消失。
6. **跨模式不自动打断写作。** Agent 等待输入、审批、完成或失败时只显示轻提示，不自动切换模式，不弹全局模态框，不抢编辑器焦点。
7. **提醒附着在“Agent”模式入口。** 截图中星光按钮是写作草稿 Dock 入口，其数字徽标只作为视觉参考；Agent 状态不占用该按钮，避免把“查看写作草稿”和“处理 Agent 任务”混为一个入口。
8. **提醒为 P1。** 输入草稿、活动会话、后台 Run 和确认表单连续性是 P0；跨模式状态图标与数量提醒在核心链路稳定后实现。

## 3. 目标与非目标

### 3.1 目标

- Agent 输入草稿在写作/Agent 切换后仍然存在。
- 多个 Agent 会话各自拥有独立输入草稿，切换会话不会串稿。
- 返回 Agent 时恢复离开前的活动会话、时间线位置和必要的 Inspector 状态。
- Agent Run 在写作模式继续执行，并能进入等待输入、等待审批、完成或失败状态。
- 用户返回 Agent 后能立即看到正确的待处理表单，并继续原 Run。
- 写作模式提供克制但可辨识的 Agent 状态提醒。
- Agent 保活不显著增加写作按键延迟和后台空闲 CPU。

### 3.2 非目标

- 不允许 Agent 在用户写作时自动修改或覆盖当前正文。
- 不把所有 Agent 进度事件做成通知、Toast 或系统通知。
- 不在本需求中重做 Agent 会话时间线、Inspector 或确认卡视觉结构。
- 不要求切走后保留已打开的菜单、Tooltip、临时 Dialog 等瞬时浮层；这些界面应在隐藏时关闭。
- P0 不承诺未发送的普通输入草稿跨应用重启恢复；该能力作为 P1 持久化增强，见第 5.2 节。

## 4. 用户场景

### 4.1 输入草稿切换

1. 用户在会话 A 输入一段尚未发送的任务说明。
2. 用户切到写作模式查看原文。
3. 用户再切回 Agent。
4. 系统仍显示会话 A 和原输入内容，光标与输入框高度合理恢复。

### 4.2 Agent 后台运行，用户继续写作

1. 用户在 Agent 模式启动任务。
2. 用户切到写作模式阅读或编辑章节。
3. Run 在后台继续接收并持久化进度。
4. 写作模式只显示轻量“运行中”状态，不抢焦点。
5. 用户切回 Agent 后看到连续时间线，而不是重新启动或重复执行任务。

### 4.3 写作期间出现用户决策

1. Run 在后台进入 `waiting_user_input`、`waiting_approval` 或章节拍确认。
2. 会话/任务层立即保存阻塞状态，并更新 Agent 入口提醒。
3. 用户继续写作，系统不弹模态框。
4. 用户点击 Agent 入口后进入发起该请求的会话。
5. 系统通过本地状态与 `runStatus` 对账，滚动到唯一的未解决表单。
6. 用户提交后，原 Run 幂等恢复，提醒同步消失或降级为“运行中”。

### 4.4 多会话同时有状态

1. 多个会话可能分别处于运行、待回答、待审批、结果待处理或失败。
2. Agent 入口只显示最高优先级状态，避免堆叠多个图标。
3. Tooltip/无障碍名称汇总各类数量。
4. 进入 Agent 后优先打开最高优先级的未解决会话；同一优先级按最早进入待处理状态的会话优先。

## 5. 功能需求

### 5.1 模式和界面状态连续性（P0）

模式切换必须保留：

- 当前 `novelId` 下的活动 Agent 会话 ID。
- 各会话未发送的普通输入草稿。
- 各会话正在填写但尚未提交的结构化问答答案，按 `runId + requestId` 隔离。
- 各会话正在填写但尚未提交的审批意见，按 `runId + checkpointId` 隔离。
- 时间线是否跟随最新消息；未跟随时恢复原滚动锚点，而不是强制跳到底部。
- Inspector 的开关、宽度、当前 Tab 和当前审核目标。
- 当前会话的附件选择、角色、章节范围和执行模式等会影响下一次提交的编辑状态。

模式切换不必保留：

- 已展开的下拉菜单、Tooltip、右键菜单。
- 尚未确认的删除 Dialog 或仅服务当前可见操作的临时浮层。
- Hover、按压态和纯动画进度。

从 Agent 切到写作也不得使当前未保存正文回退到数据库旧版本。正文编辑器可以保活，或在重新挂载时从最新 Renderer 快照恢复；不得只使用进入编辑器时的旧 `currentChapter.content`。

### 5.2 输入草稿作用域与持久化

- 草稿主键为 `novelId + conversationId`，不得只按小说或当前组件保存。
- 切换模式、切换会话和切换当前章节时，不得清除其他 Agent 会话草稿。
- 用户消息进入会话时间线后，立即且只清除本次发送所属会话的草稿；后续 Agent 响应成功、失败或取消均不恢复原输入。
- 章节范围、问答卡或 Runtime 就绪检查等前置校验未通过，用户消息尚未进入时间线时保留草稿。
- P0 至少保证同一 Renderer 生命周期内恢复。
- P1 将草稿异步写入 SQLite，使其在应用重启后恢复；写入采用 300–500ms debounce，不在每次按键时同步写 `localStorage` 或数据库。
- 草稿持久化失败不得阻塞输入；仅记录诊断并保留内存副本。

### 5.3 后台 Run 与确认表单（P0）

- Agent 任务控制器和事件订阅位于模式条件渲染之外。
- 切到写作模式不得调用 `unsubscribeRun`、取消请求或把 Run 标记为断开。
- 所有 Run 事件以 `runId + sequence` 去重和排序；普通进度允许批量投影，阻塞/终态事件立即处理。
- `user_input_required`、`approval_required`、章节拍确认、`run_completed`、`run_failed` 不得节流、合并掉或延迟到下一次进入 Agent 才持久化。
- 返回 Agent 或窗口重新获得焦点时，对所有非终态 Run 调用或复用 `runStatus` 对账，补齐 `lastSequence` 之后的事件。
- `pendingUserInput` 和 `pendingApproval` 的事实源是持久化 Run/Conversation 状态，不是某次 SSE 是否被当前 UI 收到。
- 表单提交使用 `runId + requestId` 或 `runId + checkpointId` 作为幂等身份。重复点击、断线重试或恢复后再次提交不得重复推进 Run。
- 同一个阻塞状态在对话中只能有一个可提交入口。历史卡只读，不得因保活或重放出现两个有效表单。
- 用户从写作模式进入 Agent 时，若离开前活动会话本身有未解决项，保持该会话；否则打开最高优先级未解决会话并定位表单。没有未解决项时恢复离开前活动会话。

### 5.4 Agent 入口轻提示（P1）

提示只在用户不处于 Agent 模式时强调；进入 Agent 后由工作区内部状态承担反馈。入口使用“状态图标 + 可选数量徽标”，不能只依赖颜色表达。

| 优先级 | 场景 | 建议图标/色调 | 数量含义 | 清除条件 |
| --- | --- | --- | --- | --- |
| 1 | 执行失败，需要查看或重试 | `CircleAlert`，红色 | 有未查看失败的会话数 | 用户打开对应失败位置并完成查看；重试后转为运行中 |
| 2 | 等待用户回答 | `CircleHelp`，琥珀色 | 存在未解决 `requestId` 的会话数 | 成功提交、明确关闭或 Run 取消 |
| 3 | 等待用户审批/章节拍确认 | `ClipboardCheck`，琥珀色 | 存在未解决 `checkpointId` 的会话数 | 成功提交、拒绝或 Run 取消 |
| 4 | 结果待查看 | `FileCheck2`，靛青色 | 存在未查看结果的会话数 | 点击提醒并成功定位到对应会话 |
| 5 | 后台运行 | `LoaderCircle` 或低对比度蓝色状态点 | 默认不显示数字 | Run 进入阻塞态或终态 |
| 6 | 空闲 | 无附加图标 | 无 | - |

聚合规则：

- 同时存在多种状态时，入口只展示上表中最高优先级的一种。
- 数量按会话去重，不按问题数、事件数或产物数累加，最大显示 `9+`。
- Tooltip 示例：`Agent：1 个任务待回答，2 个任务运行中`。
- `aria-label` 必须包含同等状态信息，不能只让视觉用户看到徽标。
- 运行中可以使用低频、低对比动画；等待用户和失败状态不持续闪烁。
- 状态变化不得改变整个模式切换器的宽度或导致顶栏位移。
- 不播放声音，不发系统通知，不自动展开 Agent，不在写作正文上覆盖提示层。

### 5.5 未读与待处理语义

- “等待用户回答/审批”是业务阻塞状态，打开会话不会清除，只有完成处置才清除。
- “执行失败”是注意状态。首次打开并定位失败信息后可标记已查看，但失败事实仍保留在时间线。
- “结果待查看”只表示未读状态。点击提醒并成功定位会话后清除入口提醒，但不得把产物的 `reviewStatus` 改成已审核。
- 真正阻塞执行的审核必须表现为 `waiting_approval` 或独立待改清单，不得借用已读结果徽标持续催促。
- “运行中”是瞬时状态，不进入未读计数。
- 未读游标至少按 `conversationId + runId + terminalEventId/artifactId` 保存，不能仅使用易变化的时间戳推断。

## 6. 推荐架构

### 6.1 分层

```text
EditorWorkspace
  └─ AgentWorkspace（轻量控制器随编辑器常驻）
       ├─ 会话索引与活动会话 ID
       ├─ draftsByConversationId 与表单草稿
       ├─ 多 Run 订阅、事件去重、runStatus 对账
       ├─ pending / unread 聚合状态
       └─ AgentWorkspaceView（仅 Agent 模式挂载重型 DOM）

WritingView
  └─ 通过 ref/getter 暴露最新正文快照
```

当前版本没有对约 7000 行的工作区组件做一次性 Provider 重写，而是在同一个常驻控制器内建立等价生命周期边界。控制器随编辑器挂载，以便应用重启后即使停留在写作模式也能恢复待处理任务；隐藏时组件仍持有会话、草稿、订阅和状态投影，但直接返回空视图，不保留完整时间线 DOM。确认表单是否存在由控制器状态和持久化 Store 决定，不由表单子组件是否挂载决定。

### 6.2 正文快照边界

- 不再把每次按键变化的 `currentContent` 作为普通 prop 传给隐藏 Agent 树。
- `EditorWorkspace` 保留最新正文的 ref 或稳定 getter。
- 只有在用户进入 Agent、发送请求、创建计划或执行确实需要当前正文的动作时读取一次快照。
- 快照必须包含 `novelId`、`chapterId`、内容版本或 Hash，避免用户切章后 Agent 读取错误正文。
- Agent 运行期间继续写作不会静默改变已经启动 Run 的输入；新正文只供下一次明确动作读取。

### 6.3 渲染隔离

- Agent View 首次访问前不加载重型时间线和 Inspector。
- 首次访问后允许保活，但需要 `React.memo` 或等价稳定边界。
- Host 传入稳定回调和细粒度 selector，隐藏 View 不订阅正文按键状态。
- 隐藏且空闲时暂停仅服务视觉效果的计时器、动画、ResizeObserver 和测量逻辑。
- 普通进度事件可按 100–250ms 合并一次 Renderer 投影；阻塞、失败和完成事件立即刷新。
- 长会话后续应引入时间线虚拟化或分段挂载，不能长期依赖完整历史 DOM 常驻。

## 7. 性能要求

性能验证必须使用包含长会话的真实构建或 production build，不能只凭开发环境主观判断。

### 7.1 写作输入

- Agent 从未访问时，不新增 Agent 重型 Renderer 成本。
- Agent 已访问但当前隐藏且空闲时，连续输入正文不得触发 `AgentWorkspaceView` commit。
- 隐藏 Agent 不执行正文解析，例如 `extractReadableText(currentContent)`。
- 与未访问 Agent 的基线相比，隐藏 Agent 后 95 分位单次输入到绘制延迟增加不超过 3ms，且不得出现新增的持续长任务。

### 7.2 后台任务

- 隐藏且运行中的 Agent 只因任务事件更新，不因正文输入更新。
- 普通高频进度事件合并后，Renderer 状态投影频率不高于每 100ms 一次。
- `waiting_user_input`、`waiting_approval`、`run_completed`、`run_failed` 在 Renderer 收到事件后 250ms 内更新顶栏提示。
- 切回 Agent 后，已有内存状态应在一个可见帧内呈现；需要网络对账时先显示本地持久化状态，不展示空白工作区。

### 7.3 资源

- 隐藏且空闲 Agent 的目标是“仅保留必要内存，接近零持续 CPU”。
- 不因为模式反复切换重复注册事件监听、创建定时器或累积 DOM 节点。
- 连续切换写作/Agent 50 次后，Run 事件只处理一次，订阅数和主要 DOM 数量保持稳定。

## 8. 数据与可靠性约束

- 会话、Run、`pendingUserInput`、`pendingApproval`、Artifact 和事件序列继续使用持久化 Store 作为事实源。
- UI 草稿与业务阻塞状态分开保存；清理输入草稿不得清理待回答请求。
- 切换小说时，先保存当前小说内存草稿，再加载目标小说 Host；不同 `novelId` 不共享状态。
- 删除会话前若存在运行中或阻塞 Run，沿用现有删除/取消策略，不能由本需求静默丢弃任务。
- Renderer 恢复时发现本地状态与 Runtime 不一致，以持久化 `runStatus` 和更高事件序列为准，并留下可诊断日志。

## 9. 验收标准

### 9.1 P0 自动化/契约测试

1. 会话 A 输入文字，执行 `Agent -> 写作 -> Agent`，草稿完全一致。
2. 会话 A、B 分别输入草稿，多次切换后互不覆盖。
3. A 的用户消息进入时间线后立即清除且只清除 A；后续 Agent 响应失败或取消也不恢复 A。
4. Agent Run 启动后切到写作，任务继续完成，且没有重复执行。
5. 写作期间产生 `user_input_required`，返回 Agent 后显示原请求表单和未提交答案。
6. 写作期间产生 `approval_required/chapter_beats`，返回后定位唯一有效确认卡。
7. 提交同一 `requestId/checkpointId` 两次只推进一次 Run。
8. 事件流断开后通过 `runStatus + lastSequence` 恢复，不丢失阻塞状态。
9. Agent 切换前后保持活动会话、非跟随滚动锚点和 Inspector 状态。
10. 从写作切到 Agent 再返回，未保存正文不回退。

### 9.2 P1 状态提醒测试

1. 写作模式下分别模拟运行中、待回答、待审批、结果待处理和失败，图标、颜色、文案符合映射。
2. 多状态并存时只显示最高优先级，Tooltip 汇总全部状态。
3. 数量按会话去重并在超过 9 时显示 `9+`。
4. 点击 Agent 后打开正确的未解决会话并定位表单。
5. 点击结果提醒并定位会话后清除结果未读；查看不会误清除待回答/待审批，成功处置后阻塞提醒即时更新。
6. 键盘与屏幕阅读器可以获知与视觉徽标相同的信息。

### 9.3 性能测试

1. Agent 从未访问、已访问后隐藏空闲、已访问后隐藏运行三种情况下记录 React commit 和输入延迟。
2. 隐藏空闲 Agent 在正文连续输入期间为零 View commit。
3. 普通进度事件按约定批量投影，阻塞/终态事件不被节流。

## 12. 决策记录

### 2026-07-30：采用渐进式控制器保活，不做整体 Provider 重写

当前工作区体量较大且同时包含其他在途改动。为降低回归面，本期保留 `AgentWorkspace` 作为状态控制器，并随编辑器常驻；写作模式只暂停重型视图 DOM。这样既能在冷启动进入写作模式时恢复持久化待办，也不会常驻完整 Agent 界面。后续若需要跨窗口共享 Agent 状态，再抽离独立 Provider。

### 2026-07-30：正文只在明确动作时读取

移除实时 `currentContent` prop，改为稳定 `getCurrentContentSnapshot()`。同时只向 Agent 传入 `id/title/volumeId/wordCount` 章节元数据，避免正文输入和自动保存替换章节对象时触发隐藏 Agent 更新。

### 2026-07-30：普通草稿持久化，表单半填状态留在 Renderer

普通输入草稿使用独立轻量 IPC 写入 SQLite；草稿主键沿用会话 ID，并由会话记录携带 `novelId`。结构化问答、审批和章节拍的半填状态仍属于当前 Renderer 会话，不写入 Runtime 业务事实；正式提交后才进入 Runtime 持久化状态。

### 2026-07-30：多 Run 订阅按 Run 隔离

每个活跃 Run 独立维护订阅身份和最后 sequence。切换会话只改变“当前展示 Run”，不会退订其他仍在运行或阻塞的 Run。所有订阅调用经过单一去重入口，终态、删除小说工作区或组件卸载时才清理。

### 2026-07-30：事件分两级投影

普通进度事件以约 120ms 为一批更新 Renderer；`approval_required`、`user_input_required`、`run_completed`、`run_failed` 和 `run_cancelled` 先刷新队列再立即投影，避免表单和提醒延迟。

### 2026-07-30：活动会话和已查看游标采用不同存储

活动会话 ID 是每小说的本机界面偏好，暂存 `localStorage`。普通草稿和失败/完成已查看 Run 游标进入 SQLite，保证应用重启后仍可恢复。

### 2026-07-30：入口只展示一个最高优先级状态

优先级固定为失败、待回答、待审批、结果待处理、运行中。入口只显示最高级别图标和该类会话数，其余状态通过 Tooltip 和 `aria-label` 汇总；点击后进入最早待处理的目标会话，当前会话已有阻塞表单时不强制跳走。

### 2026-07-30：窄窗口优先保留主流程入口

小于 640px 时暂时收起写作侧栏、写作视图模式和心流模式入口，保留返回、写作/Agent 切换和设置。这样不改变桌面布局，也能保证 Agent 待处理提醒在窄窗口中可见、可点且不与右侧操作重叠。

### 2026-07-30：结果徽标采用一次性未读语义

“结果待查看”不是审核状态。用户点击带提醒的 Agent 入口并定位到目标会话后，以 `conversationId + runId` 写入已查看游标并立即清除徽标；该动作不改变产物审核状态。仍需用户决策的工作必须继续使用 `waiting_user_input`、`waiting_approval` 或独立待改清单表达。

### 2026-07-30：输入内容进入时间线即清空编辑框

用户消息一旦进入会话时间线，就视为输入框已完成提交并立即清空；Agent 后续响应失败或被取消时不自动回填。前置校验失败且消息尚未进入时间线时继续保留输入。持久化用户消息时同步将该会话 `composerDraft` 写为空，避免应用重启后旧输入重新出现。

## 13. 性能评估

- Agent 从未访问时只挂载轻量控制器，用于读取会话索引和恢复持久化待办；不挂载重型视图 DOM，也不启动仅服务可见界面的轮询和测量。
- Agent 已访问但处于写作模式时，正文 `content` 和自动保存生成的完整 `Chapter` 对象均不进入 Agent props；`React.memo` 边界不会因正文输入提交 Agent 更新。
- 隐藏时 Agent 仅保留控制器状态和 Run 监听，完整时间线、Inspector、表单和附件 DOM 均卸载；Runtime 健康轮询、窗口尺寸监听和可见区滚动测量暂停。
- 后台 Run 仍会更新轻量状态投影，这是提醒和表单可靠恢复所需的必要成本；普通事件最高约每 120ms 投影一次，阻塞与终态立即处理。
- 切回 Agent 会重新构建当前会话时间线。该选择将成本从持续写作阶段移到用户主动切换的一次性动作；若 500 条以上时间线在生产构建中仍超出一个可接受可见帧，再引入分段挂载或虚拟化。
