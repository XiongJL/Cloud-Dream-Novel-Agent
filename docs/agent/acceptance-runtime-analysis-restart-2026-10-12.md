## 修复

### 桌面连接恢复

`PythonRuntimeClient` 捕获实际请求端口，避免没有 `error.port` 的旧连接错误影响新进程。连接重置或自动健康恢复先检查仍存活的进程；健康检查失败也不能证明后台任务已终止，因此保留进程并显示响应较慢。只有进程已退出时才自动启动替代进程；用户显式重启仍正常支持。

仅角色、Skill 列表/草稿读取、任务状态和事件读取可自动重发一次，且保留原请求 ID。执行计划、重试任务、聊天生成等非白名单请求丢失响应时明确报 `AGENT_RUNTIME_CONNECTION_LOST`，要求先核对原任务，避免重复启动或重复收费。

持续健康检查失败时提供显式重启入口，按钮注明会停止运行中的任务；不能将保留进程变成用户无法干预的卡死状态。

### 任务状态和检查点恢复

启动时将中断失败的状态、步骤状态、失败版本、失败对象、恢复描述与终止事件一并持久化。只读分析阶段的检查点可提供“从检查点继续”：内置文风分析，以及已进入自建 Skill 自适应分析的修订规划、编辑审查和世界观审查。

启动不自动执行收费任务。用户手动继续原任务后，保持原任务根 ID 和分片身份：复用已完成分片，核对未完成请求的保存结果，再继续剩余任务。已保存响应的本地处理失败若属于磁盘/数据库故障，保留原系统错误，不能吞掉并改报结果未知。

结果尚未核对的只读分析可以再次手动核对检查点，但仍不能盲目重发未知模型请求。真正的草稿写入结果未知、取消意图、缺失检查点和编写/编译阶段不获得分析重试授权。现有持久草稿恢复和用户确认流程继续保留。

兼容旧版只保存中断事件的失败任务：加载时补齐失败版本与恢复描述，同一记录不会每次启动重复补写。没有数据库结构或依赖版本变更。
