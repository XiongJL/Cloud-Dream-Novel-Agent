# 章节提示词与来源文风提炼：实现验收

日期：2026-10-14。对应 [实施前设计](./chapter-prompt-and-style-fidelity-design-2026-10-14.md)。

## 已实现

- 章节正文请求单独投影：原始用户意图、当前详细节拍、其他章节路线分别传入。当前节拍不再复制到 userIntent、allBeats 和外层任务参数中。上下文检查器保留完整批次；受保护 Skill 全文和冻结版本仍完整传入模型。
- 请求的显式 mode 统一系统身份、参数和正文边界。新章不会继承 preparedContext 的续写模式；章末可自然收束、过渡或悬念，由目标和节拍决定。
- 连续新增上限统一为 10，输入 Schema、节拍输出、恢复索引、持久化批次、意图数量识别和总预算同步扩展。11 章报错，不静默降为 5；批量改写保持独立的 5 章上限。
- 顺序生成：最近两章正文、早期摘要、实际状态增量和远期计划共同组成输入。最近正文不再在 Python 中悄悄裁成 12,000 字符。远期揭示标记为尚未发生；台账中的节拍事件、钩子和未核实冲突不冒充已发生事实。
- 扩展的 6–10 章批次要求实际状态核对成功。正文先按完整输入及生成版本保存检查点，核对失败停止后续生成；从原任务恢复时重试同一 Operation，复用正文，只重新核对状态。检查点损坏报错，不自动重发正文。原有 1–5 章批次保留既有警告政策。原 Operation 的次数与期限限制仍有效；明确重生成会开启新的 generationRevision。
- 内置提炼新增 1.4.0。1.0–1.3 保留，已冻结旧任务继续走原版本。新版本以语言成员为核心，悬念/群像按证据和适用场景选择，允许单成员 Pack；全局可见性、发布 CAS 和主成员加最多一个辅助的消费约束保留。
- 来源画像按章节与正文哈希保存粗略句长、段长、引语比例和有界参考片段。向模型提供最多六章代表统计及聚合分布，不把整本正文或全部逐章统计重新装入编写请求。统计描述样本，不作生成配额，也不宣称程序已完成语义场景分类。
- 至少五章时，最多保留两章作独立验收参考，排除其候选证据用于规则编写。更少样本明确标记参考未独立保留。统计缓存缺失可以从一致的冻结正文重建，不调用模型；来源改变则停止验收。
- 文档编写与审核强调条件化节奏、人物语气、心理叙述和正常长短变化；不再强制所有来源都有悬念成员，或把短句、微动作、停顿当成通篇默认。
- 新版试写对互动和过渡分别进行无 Skill、单成员和 Pack 对照；有群像成员时互动场景提供真实多人物任务。审核增加 source_fidelity、rhythm_variation；原有五项仍须通过。第二场景缺失、来源一致性未核实或降级为旧报告，不能编译发布。

## 使用与边界

新提炼选择内置 1.4.0；可先用 10 章测试来源提炼与试写，再检查全文、来源画像和对照试写结果。旧任务按冻结版本恢复，不自动换提炼器。

已发布的旧 Pack 不会被本次代码更改自动修正。需要按现有草稿流程定向修订成员并重新验收，再发布新 SkillRevision/PackRevision；原版本与用户手工内容保留。本次没有为真实 Pack 生成或发布修订，也没有真实模型试写结果，因此不能声称具体小说的文风质量或检测结果已经改善。

新增场景会增加试写/审核阶段的调用量，来源画像计算不消耗模型 token，全文分片分析不会因两场景而重复。批末草稿继续经现有审核/确认写回流程处理；本次未新增强制全书专家审核或重新分析整本小说。
