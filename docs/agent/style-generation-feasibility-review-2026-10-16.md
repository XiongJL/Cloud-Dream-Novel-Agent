# 小说文风迁移与 AI 味：可行性复核

复核日期：2026-10-16。范围：读取现有源码、交接材料、历史真实生成、十章提炼记录、两版手工修订 Skill，以及公开研究。没有运行新的付费生成、提交文本到外部检测器或修改运行中的 Skill。本文件是一份诊断与实验设计，不是改进效果验收报告。

**结论：有合理的改进路线，当前实现尚未证明路线有效；“提高小说质量”“保留来源风格”“稳定通过朱雀”必须分别验证。** 当前失败不能证明小说 Agent 不可行，也不能据此断言只要换模型、重提炼500章或再润色就能解决。

## 1. 按影响排序的发现

### 1.1 提炼产物更像写作方法，缺少足够的来源表达实例

`output/skill-review-completed-10-2026-10-13/analysis.json` 实际包含10个分析单元、80项观察、10个不同来源章节ID。对应报告也标明已分析10章。导入1—500章不等于当前使用的 Skill 已学习500章；这里只确认这批可追溯产物的覆盖，不断言用户所有历史任务都只分析过10章。

当前语言1.0.2的主张包括人物有限认知、具体用词、句段随思路变化、对白服务人物目的、删除重复功能。这些建议有用，但可以适用于大量小说。它们没有充分规定来源独有的叙述态度、解释展开方式、人物措辞差异和情绪强度变化。文件自己承认人物声音未核验。

已有来源引文至少显示：样本存在直接心理评价、情绪爆发、不同措辞和显性的叙述说明。因此不能把它概括成所有人物都冷静、全靠微动作、尽量不解释。短引文只能证明这些写法存在，不能证明其频率或全书规律。

历史 `trial-language_style.md` 相比 `trial-baseline.md` 更短，对白呈连续短问短答，夹入手部动作与停顿。这是方法影响文本的迹象，不是来源保真或质量提升的证据；两篇长度不同，也不能当严格因果实验。

关键区分：Skill是在推理时增加条件，不是在训练模型权重。把大量原文压成几条规则，不会自动保留那些没有写进规则的语言信息。

### 1.2 正式生成会继续学习目标书既有的模板

当前 `apps/desktop/electron/ai/AiService.ts:5006` 明确将 `anchorChapterReference` 与已有章节同时作为事实和文风参考。历史真实请求读取了目标书较多正文；两份方法确实进入模型边界，不能再把失败归因于“只传了Skill名称”。

当目标书旧稿已有整齐对白、动作填充和反复收尾时，这条指令提供了与新风格目标竞争的示范。**竞争确实存在于输入设计；它对质量的影响大小尚需消融实验。** 不能声称模型一定更听旧稿，或仅凭token数量推断注意力分配。

最小方向：区分事实连续性资料、前文衔接片段和明确批准的风格参考。事实保持一致不等于沿用全部措辞、节奏和瑕疵。事实资料必须保留原文回查入口，不能全靠可能遗漏状态的短摘要。

### 1.3 真实草稿的主要问题已到叙事层，普通润色难以覆盖

已完整阅读 `output/chapter-audit-2026-10-15/draft-payload.json` 的正文。重复交接、核对、巡视、记日志、信件与灯光收尾，使多段文字没有新的选择或阻力。人物的回答方式相近，部分感官因果也不成立。

例如“下巴浅痕”被直接归因为整夜没睡、“主灯旋转”接“一层，一层”，问题在意义和因果，不是缺少近义词。上午已取回执、傍晚又说回执快到，则需要核对事件状态。

这解释了为什么一般润色可能收效不大：若要求保留原情节、篇幅、段落结构，只修改表达，就会保留主要病因。有效修订有时必须删掉一整段重复功能，或重新确定人物此刻的目的。用户其他润色模型的输入输出本轮未取得，因此不能断言它们具体为何失败。

历史新章目标还重复已有末章收束，4500汉字任务可能放大填充需求。目标重复有直接记录；篇幅导致填充仍是假设。当前代码已允许篇幅调整失败时保留质量较好的正文，不能把旧问题全部当作现状。

### 1.4 新版提炼验收更完整，但仍不能替代完整场景与章节检验

`agent_runtime/novel_agent_runtime/style_fidelity.py:25` 的来源画像按标点、换行、引语做粗统计；第35行从引语段、叙述段及结尾中取单段，最多300字符。它没有语义选取完整的“判断—交锋—结果”过程。按章节位置选学习/保留资料也不保证场景类型覆盖。

`agent_runtime/novel_agent_runtime/style_quality.py:428` 的试写请求传入场景与成员文档；第456行才把独立参考片段交给审核模型。将保留集只交给审核是正确隔离，但**生成侧还缺少另选学习样本作为具体表达参考的对照组**。不能为了加强生成而把保留集泄漏进去。

新版已经有互动与过渡两类场景，这是进步；250—450字试写仍不足以验证整章取舍、几千字后的节奏漂移与连续章节表现。对照审核暴露了哪个样本是待验收目标，也不等同于完全隐藏条件的人类盲评。

## 2. 关于朱雀：承认外部门槛，但不要混淆测量对象

腾讯官方把朱雀描述为AIGC来源检测。其接口分别返回类别占比、整体置信度与分段标签。没有当前网页结果的完整字段与说明，不能把“100%疑似AI”解释为“100%差文”“100%概率为AI创作”或认定网站百分比等于某个API字段。

官方接口说明：<https://cloud.tencent.com/document/product/1552/137539>。

研究支持把风格相似性与可检测性分开：Jemama与Kumar在其文章样本实验中发现，提供示例与续写上下文能改善风格匹配，但高匹配仍伴随不同统计特征。该实验不是中文长篇小说，也没有证明能通过朱雀。

来源：<https://arxiv.org/abs/2509.24930>。

StyloBench对文学与博客风格模仿的研究发现，多种检测器在个性化场景下表现不稳定。这说明检测结论需要场景内校准；不证明朱雀在本项目中误判，更不能据此承诺规避检测。

来源：<https://aclanthology.org/2026.acl-long.1998/>。

如果通过朱雀是实际交付要求，应单独保留这一验收门槛。可能出现质量改善但分数不降，也可能分数下降但小说变差；两者都必须如实报告。

## 3. 最值得先验证的方案

**优先验证“简短方法＋按场景选的完整参考＋明确的故事任务”，再判断是否值得换模型或训练。** 这是工程假设，尚未在本项目验证。

1. 保留现有提炼结果，回到已导入正文选少量完整场景，不重新付费提炼整书。覆盖交锋、思考/解释、普通转场、情绪变化；不要只取开头密室或名场面。初始可选6—10段、每段约400—800汉字，数量是实验预算建议，不是最佳值。
2. 学习参考和验收参考按章节或相邻情节块隔离。每次只给生成侧1—2段匹配场景功能的学习参考，保留足够上下文理解起因和结果。
3. 为参考注明“表达材料”，将来源人物、规则、道具及剧情与目标故事事实分开。检查迁移后的内容是否出现来源专名、连续长句重合或情节挪用。风格迁移不应靠改名复写源场景。
4. Skill保留少量有证据且可操作的特征、适用条件和边界，不把全部审核日志、禁令和统计配额当作写作方法。已经承诺完整加载的产品契约仍需遵守，实验使用新候选或明确选用的版本，不能运行时悄悄裁剪。
5. 正文写作前先确定人物想得到什么、阻力是什么、这一场结束时什么改变了。节拍不必预写每个动作和意象。普通转场允许简短，也允许没有悬念。
6. 如果章节实验显示整章生成会漂移，再试按自然场景顺序生成，并携带已写正文末段、状态和未完成事项。不要固定每几百字机械切块，更不要在每块末尾都造钩子。
7. 修订针对具体功能：删重复交流、调整误判过程、恢复人物不同诉求。保留初稿比较，不使用无限次“去AI味”重写循环。

模型值得比较，但先让不同模型接收相同输入，避免把新提示词的收益算到模型头上。微调/LoRA是后续候选，需要适合的授权语料、独立验证、成本与记忆复现评估；500章文本本身不等于合格训练集，也不保证检测通过。现在就训练缺少投入依据。

## 4. 第一轮实验：8篇短场景，定位方向

先冻结事实与场景，不使用旧稿已经结束的章目标，不调用模型随机规划节拍。一个场景写利益冲突与判断修正，一个写事情结束后的普通转场。两者采用相同的约800—1200汉字宽范围，初筛不自动修字数；记录实际长度，过短或未完成者算任务失败，不能因简短显得利落就获胜。

| 组别 | 条件 | 定位的问题 |
| --- | --- | --- |
| A | 固定事实与任务，无风格Skill、无来源参考 | 当前模型在干净输入下的基线 |
| B | A＋现有语言1.0.2 | 规则单独是否有收益 |
| C | A＋1—2段学习集完整场景参考 | 具体示例能否补足表达信息 |
| D | A＋同一语言1.0.2＋与C相同参考 | 规则帮助示例迁移，还是相互干扰 |

每组各写两种场景，共8篇，模型、温度、输出预算、事实、目标和长度要求一致。必要的衔接片段在四组中保持一致，明确不自动继承其语言缺陷；第一轮不加入悬念辅助Skill，避免多因素混杂。记录完整请求、Skill修订ID、参考哈希、模型服务标识、用量和结束原因。

预先准备的场景事实可采用以下原创素材；它们不是《十日终焉》风格示例：

- 交锋：维修员必须在闭馆前取回工具；管理员要留人核对一笔未经同意的借用；徒弟知道实情但怕丢工作。工具实际没有丢失。场景中至少一人的判断因他人的话而修正，达成有代价的临时安排。不能加入秘密组织、血案或神秘讯息。不给固定对白和动作顺序。
- 转场：比赛已经输掉，结果不会翻转；一人准备退出队伍，另一人不知道；两人整理场地、商量下次是否来。允许直说、沉默和琐事，但场景要改变两人的约定。没有谜题或反转要求。

使用真实目标小说场景时，应替换为它自己的角色和事实，并在四组开始前冻结；上述素材仅提供低依赖的实验选项。

先隐藏生成条件和检测分数，随机排序由用户比较：

- 是否完成任务、没有因果错误与信息反复？
- 人物是否有不同目的、判断与说话方式？
- 哪些段落推动行动或关系，哪些只是填充？
- 是否出现机械的动作插入、对白停顿与多次收尾？
- 对照独立来源场景，哪些具体表达机制相近，哪些只是同属悬疑题材？

每个偏好必须指向具体句段，允许平局。模型可辅助找证据，不能用它自己的“pass”代替用户阅读。再看朱雀结果，记录入口、日期、全文长度、原始结果及分段方式，不只摘一个总分。

检测控制组另行准备：至少几段明确由人写的目标作者/用户文本，以及长度接近的已知AI文本。不能从三五条控制组推出总体误报率；目的仅是发现当前入口、长度与文体是否导致明显异常。未有对应账号/接口和明确样本前，本轮不假装已完成检测。

第一轮8篇只筛方向。对最佳条件与A在两个场景各重采样一次，再加4篇检查偶然性；仍有收益后，用未参加筛选的第三个场景和完整章节验证。若均无改善，用另一个候选模型重复A与最佳条件的两种场景，共4篇，区分当前模型局限与输入方法问题。总预算按阶段决定，不能未经判断自动跑完所有组合。

结果解释：C优于B提示规则压缩损失值得处理；D劣于C提示规则存在干扰；只有特定场景改善提示迁移有条件；只换模型才改善提示生成能力重要。这些都是诊断线索，小样本不能证明唯一原因。短场景改善但整章退化时，应进一步测试上下文污染、情节容量与生成粒度。

## 5. 产品改动应由实验结果决定

如果参考场景有效，优先增加可追溯的来源学习片段附件、按场景选择、与目标事实隔离和来源重合检查，而不是继续加禁词。保留验证集独立，记录本次真正使用哪些参考；跨小说调用应确认引用可访问且版本不变。

如果旧稿语言显著拖累结果，再增加“继承已有文风/采用已选风格”的明确策略；不能在所有续写场景一律丢弃前文声音。若复杂编排不如干净输入，先精简写作边界和目标，再增加Agent步骤。

如果人类盲评持续改善但朱雀仍不过，准确结论是“文学质量方向有效，检测门槛未解决”。如果参考和模型交叉实验都没有稳定收益，应缩小全自动成稿承诺，转为作者决定场景与关键表达、Agent负责候选和定向修订。不能用工程测试通过或更多重写次数宣称文学效果已解决。

本次新增此评审文档，未修改业务代码，因此没有新增或重跑代码测试。当前尚缺：修复后的真实章节样本、其他润色模型的成对输入输出、独立完整来源场景、同条件朱雀结果。现有证据足以选择下一步实验，不足以发布“已解决AI味/已稳定过检”的结论。
