## 1. 真实对话与计划

1. 切换到 `Agent` 模式。
2. 发送一个普通讨论问题，例如：`这一章的冲突是不是出现得太晚？先只讨论，不要执行。`
3. 发送后确认助手侧立即显示“思考中...”；正式回复或首个活动状态出现后该提示原位消失，不应长时间空白，也不应与正式输出同时存在。
4. 确认返回的是模型生成的具体回答，不是固定模板；在 `chat_only` 下不应出现工具调用或草稿，在 `review_required` 下可以出现与问题直接相关的白名单只读探索，但不应出现草稿或其他副作用。
5. 发送明确任务，例如：`请质检当前章节的节奏、人物一致性和追更欲望，并给出修改草稿。`
6. 确认出现结构化计划草稿，步骤、Agent 和工具名称合理。
7. 修改计划后点击 `提交`，确认计划仍保持同一个任务上下文且修改生效。
8. 发送范围不明确的任务，例如：`大纲新增一部分。`，确认 Agent 先询问新增类型且不生成计划；回答具体范围后才生成计划。
9. 完成一次带最终报告的任务后发送：`按上面的总结继续生成草稿。`，确认 Agent 能引用报告内容，不会重新询问已经回答过的范围。
10. 在世界观角色下要求新增大纲或设定素材，确认计划包含 `creative_assets.generate_draft`，完成后出现草稿；最终报告不应凭空出现计划中没有的“读者视角评估”。
11. 将会话向上滚动离开底部，确认出现“查看最新”；新消息到达时不抢走历史阅读位置。点击按钮或手动滚到底部后，确认后续消息和执行进度自动跟随到底部。
12. 使用响应较慢的真实模型发送聊天和计划请求，确认“思考中...”持续显示且不会在 60 秒固定中断；若超过扩展预算，提示应替换为可理解的中文超时错误。

通过标准：`chat_only` 的普通讨论不调用项目工具；`review_required` 可为回答项目事实执行必要的只读探索；范围不明确且工具无法补足用户偏好时必须等待用户回答；明确且信息充分的生成或修改任务形成可审核计划；计划修改不会丢失会话或产生重复计划；Run 完成后会话上下文仍连续；生成型任务必须产生对应的可审核草稿。

## 2. 审批与权限边界

1. 在计划生成后、点击 `实施此计划` 前观察工具记录和草稿审核区。
2. 确认未批准时只可能出现 `chapter.get`、`rag.ask`、`plotline.list` 等白名单只读探索记录，不得出现草稿生成、DraftSession 创建、数据修改或正文写回记录。
3. 点击 `实施此计划`，确认执行开始并持续显示步骤和工具状态。
4. 遇到分析范围确认时，分别测试一次有限范围选项和一次较大范围选项。
5. 若出现证据质量或创作方向确认，选择一个选项并提交，确认 Run 从等待状态继续执行。

通过标准：`chat_only` 不调用项目工具；`review_required` 的只读探索可在回答或计划形成前执行并留下审计记录；草稿、写回和其他副作用工具只发生在明确批准之后；确认卡提交后只恢复一次，不重复执行已完成步骤。

## 3. 长任务与实时事件

1. 执行一个包含 RAG、质检和草稿生成的多步骤任务。
2. 观察步骤状态是否按 `等待 -> 执行中 -> 完成/失败` 更新。
3. 确认工具调用、工具结果、确认卡和草稿卡按实际顺序出现。
4. 等待任务结束，确认最终状态为完成或给出明确失败原因。
5. 确认会话流出现针对原始任务的最终综合报告，而不只是步骤标题和 `run_completed` 事件。
6. 打开 Inspector 的“产物”页，确认报告型任务至少有一个最终报告产物，生成型任务同时有对应草稿产物。
7. 切换到其他会话再切回，确认历史事件、步骤状态、最终报告和草稿引用仍存在。

通过标准：无重复事件、无状态倒退、无永久卡在执行中；终态与实际结果一致；`completed` 前必须已有可读的最终报告。

## 4. 页面刷新恢复

分别在以下时机按 `Ctrl+R` 刷新窗口：

1. Run 正在执行时。
2. 页面显示 `需要你确认` 时。
3. 草稿已生成但尚未写回时。
4. Run 已完成后。

每次刷新后确认：

- 当前小说、会话和 Agent 模式可以恢复。
- 已持久化的消息、计划、步骤和执行事件仍存在。
- 活跃 Run 能继续接收后续事件。
- 等待确认的卡片仍可提交。
- 已完成 Run 不会重新显示为执行中。
- 草稿卡和 `draftSessionId` 不丢失，右侧审核区仍能读取草稿内容。
- Inspector 中的结构化产物、状态和引用不丢失。

通过标准：刷新前后不存在终态、事件、审批或草稿引用丢失。

## 5. 草稿审核与写回

1. 打开生成的章节草稿，确认宽幅审核中心正常展开，原文与 Agent 草稿都能显示，原文区不出现 Lexical JSON。
2. 切换 `对照 / 原文 / 草稿` 三种模式，确认长文可以独立滚动，标题、字数和底部操作不会遮挡正文。
3. 修改 Agent 草稿，点击 `保存修改`。
4. 刷新窗口，确认修改后的草稿仍存在。
5. 点击 `确认写回`，返回写作模式核对章节正文；确认保存内容仍是合法 Lexical 文档，没有出现 JSON 后直接拼接正文。
6. 对旧版本生成且内容可能已误拼接的草稿不做编辑，直接点击 `确认写回`，确认写回路径会先规范化内容。
7. 再生成一份草稿并点击 `丢弃`，确认该草稿不可继续写回。
8. 确认对应产物状态在写回后变为 `committed`，丢弃后变为 `discarded`。

通过标准：保存只更新 DraftSession；确认写回后正文内容与审核稿一致；丢弃不会修改正文；版本冲突时给出错误而不是覆盖新版本。

## 6. 主动取消

1. 启动一个较长的生成任务，在草稿创建前点击取消。
2. 确认 UI 依次显示正在取消和已取消，不显示为普通失败。
3. 等待至少 30 秒，确认没有迟到的工具结果或草稿出现。
4. 刷新窗口，确认 Run 仍为已取消。

通过标准：取消能中止上游模型/CLI 请求；只产生 `run_cancelled` 终态；取消后不生成迟到草稿。

## 7. Runtime 中断恢复

此项可选，适合能观察开发终端时执行：

1. 让 Run 停在“需要你确认”，终止 Python Agent Runtime，等待桌面端重新拉起后提交选择。
2. 确认 Run 从原 checkpoint 继续，审批前已完成的工具没有重复执行。
3. 另启动一个正在执行慢工具的 Run，并在工具返回前终止 Runtime。
4. 刷新或重新进入会话，并确认可以启动新任务。

通过标准：`waiting_approval` Run 跨 Runtime 重启保留确认卡并能继续；中断在未知副作用窗口内的 `running/cancelling` Run 明确标记失败，不显示为仍在执行；新任务可以正常启动。

## 8. 写作模式回归

1. 在写作模式编辑并保存章节。
2. 测试 `发送给 Agent`、`质检章节`、`下一段` 三个快捷入口。
3. 在写作与 Agent 模式之间来回切换。

通过标准：正文编辑和保存不受影响；快捷入口进入正确会话目标；切换模式不丢失未完成的 Agent 会话状态。

### Agent 模型控件

1. 在 AI 设置中配置 HTTP Provider 和模型，进入 Agent 模式，确认输入框下方显示同一个模型名称。
2. 在模型控件中修改模型并应用，发送一条新消息，确认请求使用新模型；重新打开设置页，确认配置已经同步。
3. 切换为 MCP CLI Provider，确认模型控件显示 `MCP CLI` 和实际 CLI 路径，不提供无效的 HTTP 模型应用按钮。
4. 模型配置读取或保存失败时，确认错误留在弹层内且不阻塞已有会话阅读。

通过标准：Agent 模型控件与 Electron AI 设置保持单一数据源；切换只影响后续调用，不清空或终止当前会话。

## 9. 项目上下文任务与澄清边界

1. 在大纲角色中发送“新增一段大纲”，确认系统直接生成可审核计划，不要求粘贴已有大纲或指定工具能够读取的当前进度。
2. 确认回答前允许执行 `plotline.list` 等只读探索；生成的计划仍包含创作素材草稿工具，批准计划前不得执行草稿生成或写回工具。
3. 新建会话，依次发送“新增一段大纲”“你先查看当前大纲内容”“直接补”“主线”，确认不会持续重复追问，并且生成计划的目标保留前面各轮要求，而不是只剩“主线”。
4. 发送真正缺少用户创作决策的请求，例如“把叙事视角改掉”但不说明目标视角，确认系统只提出一个聚焦问题并等待回答。
5. 发送能力咨询“你能帮我分析大纲吗？”，确认系统正常回答能力说明，不自动生成计划。

通过标准：工具可读取的项目事实不会触发澄清；只读探索可以在回答前执行，草稿和有副作用工具仍严格发生在计划批准后；用户短答能与此前任务合并；真正的用户偏好缺失仍会暂停等待。

## 10. LangGraph 主动探索

1. 在大纲角色发送“先查看当前大纲，告诉我主线还缺什么”，确认回复前出现 `plotline.list` 读取标签，并基于真实大纲回答。
2. 发送需要结合章节与设定的问题，确认 Agent 可以连续读取多个只读工具后再回答，而不是要求用户粘贴项目内容。
3. 切换到“只讨论不执行”，确认不出现任何读取标签和工具调用。
4. 请求直接写回大纲或正文，确认聊天探索阶段不会调用 `outline.write`、`chapter.save` 或草稿生成工具。
5. 使用同一会话连续提问，重启 Renderer 后继续，确认会话可继续使用且 `agent_graph.db` 不影响现有 AgentConversation 恢复。

通过标准：只读探索自动执行且结果进入回答；第四轮提出的读取会实际执行；越权工具被拒绝；软限制后仅在有进展时扩展，硬限制不超过 8 轮探索判断或 12 次工具调用并生成最终总结；原有计划审批和草稿审核边界不变。

## 11. 折叠式实时活动流

1. 启动一个包含多个读取工具和草稿生成的任务，确认会话中只有一条过程摘要持续原位变化，没有连续堆叠“正在……”消息。
2. 确认步骤标题、工具调用和审批提交记录没有在活动摘要下方重复形成助手聊天气泡；任务结束后只显示最终综合回复。
3. 点击活动摘要，确认按真实顺序显示模型阶段、LangGraph 节点、工具名、脱敏参数、结果摘要、耗时和状态。
4. 触发一个工具失败和一次用户审批，确认折叠摘要分别显示失败或“需要你确认”，展开明细保留原因和恢复记录。
5. 执行包含命令调用的任务，确认展开后显示命令、cwd、退出码和 stdout/stderr 摘要，但不出现 token、API key 或 Authorization header。
6. 展开活动流后向上滚动并等待新事件，确认不会抢夺滚动位置；回到底部后恢复自动跟随。
7. 分别在执行中和完成后刷新页面，确认摘要、明细、顺序与终态可由持久化事件恢复。
8. 使用键盘和减少动态效果设置测试展开/收起，确认焦点、`aria-expanded`、状态通知和动画行为正确。
9. 将 Electron 窗口恢复到默认 1200px 左右，确认 Inspector 可以完全折叠且对话区随之扩展；折叠后发送消息或产生新 Run，确认 Inspector 不自动打开。重新展开后恢复原标签和选择。继续缩窄至 1180px 以下，确认左侧会话导航改为可开关抽屉；缩窄至 1040px 以下，确认 Inspector 改为可开关右侧抽屉，遮罩和关闭按钮均可收起。

通过标准：活动折叠态稳定且持续更新，展开明细可审计并与事件一致；Inspector 折叠不阻断主流程、不被事件强制展开且能恢复用户选择；刷新和重连不丢失；不暴露隐藏思维链或敏感信息；长参数和输出不会撑坏布局。

## 12. FastMCP 工具传输

1. 重启桌面应用并读取 Agent Runtime `/health`，确认 `toolTransport` 为 `fastmcp`。
2. 触发一次只读探索和一次已批准草稿生成，展开活动明细，确认两者都显示 `传输 fastmcp`。
3. 在计划批准前请求草稿或写回，确认 FastMCP 不会绕过现有审批边界。
4. 执行一个缺少必填参数的工具请求，确认在进入 Electron AutomationService 前被 FastMCP schema 拒绝。
5. 执行慢工具后主动取消，确认 requestId 能穿透 FastMCP proxy，Run 进入 `cancelled` 且不产生迟到草稿。
6. 以 `NOVEL_AGENT_TOOL_TRANSPORT=http` 启动 Runtime，确认 `/health` 返回 `http`，同一只读任务仍可完成且活动明细显示 HTTP 回退。

通过标准：默认工具链真实经过 FastMCP；参数 schema、权限边界、错误和取消语义保持有效；HTTP 回退不改变任务结果契约。

## 13. 多模型上下文与长会话

1. 在同一会话中连续发送超过 20 条短消息，最早一条写明“必须保持第一人称”，最后发送“按最早的约束继续”，确认 Agent 能引用该约束。
2. 完成一个含最终报告和草稿 artifact 的任务后继续发送“按上面的结论修改计划”，确认会话不失效，且新计划能识别上一轮报告、计划与草稿状态。
3. 在 AI 设置把上下文窗口设为较小的有效值（例如 8192），继续长会话，确认请求能够完成而不是由 Provider 返回超限错误；开发日志应出现压缩/省略诊断。
4. 确认助手回答前出现“已压缩较早上下文”，展开后能看到保留原文、滚动摘要、未纳入消息和 Token 预算；刷新页面后提示仍在。短会话没有发生压缩时不得显示该提示。
5. 将窗口恢复为 `0`，分别切换 HTTP 模型和 MCP CLI Provider 后继续同一会话，确认历史消息没有被删除，下一次请求按新预算重新组装。
6. 生成较长的章节草稿和创作素材草稿，确认实际生成 prompt 与预览都使用 `agent-context-v1` 外层，草稿仍进入原 DraftSession 审核流程。
7. 打开 Inspector“上下文”，确认最新一轮显示模型、窗口、输入/输出/安全预算以及原文、摘要、精简、省略的消息范围；刷新页面后诊断和本轮只读工具来源仍在。未压缩的短会话应显示“完整纳入”，但时间线中不出现压缩提示。
8. 触发一次真实长会话压缩，确认 Inspector 新增“持久上下文摘要”，显示 revision、覆盖消息数、用户决策和 artifact 引用；刷新应用后该卡片仍在，原始消息数量和正文不变。
9. 在摘要覆盖的旧消息中放入唯一短语，随后用该短语或对应 `messageId` 提问；确认 Inspector 显示按引用召回消息。完成一份审核 Artifact 后用标题或 artifactId 追问，确认只召回有界产物摘录，而不是把完整长报告常驻每次 prompt。

通过标准：固定 20/12 条边界不再影响会话；当前请求、明确约束、待审批决策和当前计划始终保留；模型切换不结束会话；压缩不修改持久化历史；增量摘要可恢复且每个结论可追溯到 messageId/artifactId；Inspector 能说明本轮上下文如何进入模型。

## 14. 章节 Toolchain 与结构化审核

1. 在已有当前章节的编辑或世界观会话中发送“检查当前章节的一致性和前后矛盾”，确认计划步骤显示 `chapter.consistency_review@1.0.0`，并且该步骤不再同时列出一组原子 tools。
2. 批准计划，确认折叠活动首先显示一条“章节一致性审核”链；展开后按顺序看到 context 节点和底层 `chapter.get`、列表工具、`rag.ask`，每个发起/结果在 UI 中合并成一项。
3. 任务完成后打开 Inspector“产物”，确认显示一致性总分、维度评分、问题严重度、位置、修改建议和不确定性；完整审核正文默认折叠，不显示原始模型 JSON。
4. 确认任务只生成 `consistency_review` 和最终 `report` Artifact，没有 DraftSession，也没有正文/结构化资料写回。
5. 暂时让一个可选列表源失败，确认任务仍以部分 ContextBundle 完成并显示资料警告；让目标 `chapter.get` 失败，确认 Run 以 `CONTEXT_INSUFFICIENT` 失败。
6. 分别以 FastMCP 默认传输和 HTTP 回退执行同一任务，确认结果结构一致；执行中取消，确认 Run 进入 `cancelled`，不会继续生成审核。

通过标准：稳定 ID/版本可见且锁定；链节点遵守调用预算和只读边界；部分失败、取消和证据不足可审计；结构化审核易读且不创建草稿副作用。

## 15. P1 草稿 Toolchain 与未知结果恢复

1. 在已有当前章节的作者会话中发送“接着写当前章节”，确认计划只有一个 `chapter.continuation@1.0.0` 草稿生产步骤，不同时出现 `chapter.generate_draft` 原子步骤。
2. 当 Agent 给出两个互斥创作方向时，确认活动流停在“需要你确认”，批准前 DraftSession 数量不变；选择方向后只生成一个章节 DraftSession，并在审核中心显示对应 `chapter_draft` Artifact。
3. 在世界观会话中发送“新增一个与当前主线有关的角色”，确认计划使用 `creative_asset.draft@1.0.0`；展开活动流可看到五类资料读取、冲突预检、生成和校验节点。
4. 完成后确认素材 Artifact 与校验结果引用同一个 DraftSession，校验警告可读；运行过程没有调用 `draft.commit`、`chapter.save` 或其他直接写回方法。
5. 在草稿请求发出后模拟 60 秒超时或强制结束 Runtime，重新进入会话后确认 Run 显示 `SIDE_EFFECT_UNKNOWN`，不会自动生成第二份草稿；先检查审核中心，再由用户重新批准新 Run。
6. 在方向审批卡出现时重启 Runtime，确认 `waiting_approval` 可恢复并继续；重启后链版本仍为最初批准的 `1.0.0`。

通过标准：草稿链是唯一生产者；审批前零写入；每个写调用只有一个持久化 requestId；未知写结果明确失败且不重放；最终只产生待审核 DraftSession/Artifact。

## 16. P2 情节线长范围分析

1. 在编辑会话中发送“分析主线支线和未回收伏笔”，不说明范围，确认计划使用 `plotline.analysis@1.0.0`；实施后应先出现范围确认卡，批准前不得调用 `plotline.list`、`chapter.list` 或 `rag.ask`。
2. 选择“分析当前卷”，展开活动流，确认先读取情节线与卷结构，再通过多次 `chapter.list` 分批读取；每批参数包含递增的 `offset`、有界 `limit` 和 `includeContent=true`。
3. 在范围确认卡出现时重启 Runtime，确认卡片和链版本保持，提交后从原 checkpoint 继续且不会生成第二个 Run。
4. 明确发送“分析整本小说的长期停滞情节线”，确认无需再次询问范围，但 coverage 显示总章数、实际分析章数和预算省略章数；到达预算后活动流明确显示跳过，而不是静默漏章。
5. 完成后打开 Inspector“产物”，确认显示情节线健康度、范围、已读/省略章数、主线/支线推进度、风险、待回收伏笔、建议和不确定性；完整 Markdown 默认折叠。
6. 确认本次只生成 `plotline_analysis` 和最终 `report` Artifact，没有 DraftSession，也没有 `chapter.generate_draft`、`creative_assets.generate_draft`、保存或写回调用。
7. 分别用 FastMCP 和 HTTP 回退执行当前卷分析，确认结构契约一致；刷新会话后结构化分析仍可恢复。

通过标准：范围不会被模型擅自扩大；分页参数和覆盖统计可审计；预算截断明确；证据只引用真实情节线/章节；全链只读且 Inspector 可读。

## 17. 写作页移交与多章节范围

1. 在写作页打开一个明确章节，点击“发送给 Agent”，发送“帮我校验这篇文章”。
2. 确认左下角显示正确小说和章节，Agent 直接读取当前章，不调用 `volume.list` 后让用户重新选择章节。
3. 依次选择当前章、非连续多选、连续区间、当前卷和整本小说，确认范围标签、计划卡和最终报告一致。
4. 对非连续章节范围执行只读审核，确认选中章节按作品顺序固定；中间章节只能作为连续性上下文，不进入目标 finding 或写回目标。
5. 在计划生成后扩大范围或增加章节，确认旧计划不能直接实施，必须按新范围重新审批。
6. 使用 21 章以上范围，确认自动进入分批摘要模式，并显示正文覆盖、摘要覆盖、未覆盖范围和原因。

通过标准：Renderer 显式范围高于模型推断；模型不得自行扩大到当前卷或整本；范围变化必须重新审批；范围身份在刷新和后续消息中不丢失。

## 18. 六类角色与团队报告

1. 作者：对 2 至 3 章执行范围修订审核，确认生成 `writer_revision_plan`，包含文风漂移、场景强弱、改写顺序和续写准备度。
2. 编辑：执行范围审核，确认生成 `chapter_range_review`，包含结构、节奏、动机、连续性和文字质量 finding。
3. 读者：按连续章节执行盲测，确认生成 `reader_journey`，显示困惑、情绪、悬念、弃读风险、追更动力和逐章变化。
4. 在后续章节植入唯一关键词，重新盲测前序章节，确认前序模型回答、证据和 finding 不出现该关键词，也不引用世界观后台条目。
5. 世界观：确认 `worldbuilding_consistency` 只引用范围章节和已登记实体，不把模型虚构实体当作项目事实。
6. 考据：确认 `research_fact_check` 区分章节证据、RAG 和项目全文搜索；在外部网络 Tool 尚未接入时明确显示“未进行互联网检索”，不得伪装成外部来源。
7. 团队：只勾选编辑、读者和世界观，确认仅执行这三类专家；每类保留独立子 Artifact，综合报告不生成未执行专家的结论。
8. 在 Inspector 折叠状态下，确认对话报告卡仍可查看摘要、关键建议、选择处理方式并发起修订；主动打开专注审核后，确认可切换专家、查看覆盖率、严重度、章节矩阵、证据和完整 finding。关闭后回到原对话滚动位置。

通过标准：六类角色产物与职责一致；所有 finding 可追溯到范围内章节、登记资料或真实检索证据；读者严格顺序盲测；团队 Supervisor 不伪造专家或证据。

## 19. 报告建议、过期与当前对话修订

1. 在 Inspector 折叠状态下，从对话报告卡分别选择“帮我修改”“稍后处理”和“忽略建议”，确认决定、创作约束和审核备注刷新后仍存在。
2. 按章节、专家或严重度选择多条建议，确认提交前显示事项数、涉及章节和冲突提示，未选中的建议状态不变化。
3. 点击“修改选中项”，确认不跳转任务池、不新建会话；当前对话只出现一条原位更新的 `RevisionWorkBatch` 进度。
4. 展开进度，确认显示稳定的 `第 N/M 项修订` 清单；工具调用、模型请求和网络重试只进入当前事项明细，不改变 M，也不形成独立聊天气泡。
5. 对小范围单章修订，确认不额外要求审批形式化计划，但只生成 DraftSession、不写正文；对跨多章结构调整或范围不明确任务，确认先出现简洁修订方案。
6. 同一章节选择多条建议，确认可以共享一个草稿生成单元，但每条建议仍保留来源和状态；后续事项失败时已完成事项不重新执行。
7. 在最终草稿/diff 审核前检查正文和章节版本，确认没有自动修改；确认写回并完成复核后任务才自动标记解决。手动解决必须填写原因。
8. 分别在作者、编辑、读者和综合视角选择“稍后处理”，确认建议进入同一个“待改清单”；默认只显示待处理、处理中、已完成、已失效，按章节、人物、情节线和来源视角的筛选可按需展开。
9. 在报告生成后手动修改源章节，再发起修订，确认报告和任务标记为过期，仍可阅读但不能直接生成草稿。

通过标准：创作者在任何 AI 工作视角下都可以在当前对话完成建议选择、修订和结果确认；切换视角不引入另一套任务管理界面；正常流程只有“选择要改的建议”和“确认最终草稿”两个决策点，高风险修订才增加方案确认；Inspector 折叠不阻断操作；建议决定和草稿审批状态独立；过期报告不能驱动自动修订；乐观锁冲突给出明确提示而不是覆盖另一窗口的决定。

## 20. 多章连续续写

1. 在非卷末章节选择连续续写 2 章，确认计划使用 `chapter.sequence_continuation`，目标数量在 1 至 5 章内。
2. 实施计划后确认先生成章节节拍，包含标题、章节目标、冲突、关键事件、信息揭示、结尾钩子和目标字数。
3. 修改一个节拍并提交，确认节拍确认前没有 DraftSession 或正文生成调用。
4. 确认正文按章节顺序生成；下一章上下文包含上一章完整草稿和人物、关系、认知、物品、冲突状态台账。
5. 在某章生成失败时确认立即停止，前序草稿保持可审核，后续章节保持 `pending`。
6. 提交前确认必须选择“当前章后插入”或“卷末追加”；生成阶段不得提前在章节树创建新章节。

通过标准：节拍审批前零正文生成；每批最多 5 章；顺序依赖和失败边界正确；只有用户提交草稿时才创建新章节。

## 21. 已有章节批量改写

1. 显式选择同卷 2 至 3 章发送“批量改写这些章节”，确认计划使用 `chapter.batch_rewrite@1.0.0`。
2. 尝试选择跨卷章节或超过 5 章，确认系统拒绝或要求重新选择，不静默缩小或扩大范围。
3. 审批逐章节拍后确认每个子草稿绑定真实 `targetChapterId`，草稿语义是完整替换正文，不是追加到原文末尾。
4. 在生成后、提交前从写作页修改任一目标章节，再提交批次，确认整次零写入并显示版本冲突，不自动合并或强制覆盖。
5. 对无冲突批次提交连续前缀，确认只替换所选目标章节，未提交章节保持原文。

通过标准：只改写显式选择的同卷 1 至 5 章；目标顺序、原文和版本快照固定；冲突时事务整体失败且正文零变化。

## 22. 批次审核、过期传播与重新生成

1. 打开 `chapter_draft_batch` 宽幅审核中心，确认批次摘要、章节轨道、节拍、逐章状态和原文/草稿对照可读。
2. 编辑并保存第 N 章草稿，确认第 N+1 章及之后依赖草稿变为 `stale`，内容仍保留但提交按钮不可越过过期章。
3. 点击“从这里重新生成”，确认新 Run 从首个失败或过期章节继续，保留此前可审核前缀和已确认节拍。
4. 选择提交前 1 章或前 2 章，确认只能提交连续、非过期的绝对前缀，不能跳过中间章。
5. 丢弃剩余批次，确认已提交章节不回滚，未提交草稿不可再写回。
6. 模拟生成请求已落盘但响应超时，确认显示 `SIDE_EFFECT_UNKNOWN` 并禁止直接重新生成。
7. 在人工对账中检查工具、批次、子项、生成修订、requestId 和候选摘要；分别验证“接纳已有草稿”和显式“确认未创建”。
8. 对账完成后确认不会立即调用模型；只有用户再次触发重新生成才创建后续 Run，旧 invocation 不自动重放。

通过标准：父子草稿、过期传播、连续前缀提交和重新生成边界一致；未知副作用必须先精确对账；界面不提供强制覆盖或忽略风险入口。

## 23. 多章节刷新、取消与会话连续性

1. 分别在团队专家并行执行、读者逐章执行、节拍等待审批、子章生成和批次审核时刷新窗口。
2. 确认会话、范围、专家选择、父子 Artifact、DraftBatch、审批卡和活动流顺序恢复，已完成步骤不重复。
3. 在团队执行和多章生成中主动取消，确认同一 Run 的并发请求全部撤销，后续不出现迟到报告或草稿。
4. 在一个多章节任务完成或终止后发送新消息，确认消息出现在旧任务之后并开启新一轮，不插入旧任务卡之前。
5. 手动向上滚动后发送消息，确认出现“查看最新”；点击后回到底部并恢复自动跟随。

通过标准：刷新、重连、取消和后续对话都不破坏时间线；终态不会倒退；同一工具发起与结果在活动明细中合并展示，过程文案不会泄露成独立助手回复。

## 24. 创作者体验收敛（重设计后）

1. 执行包含三个 AI 工作视角的审核，确认对话只出现一张综合报告卡；首屏展示 3 至 5 项，专家子报告、完整证据和真实分歧按需展开。
2. 从审核到修订完成，确认对话只保留报告卡、原位修订进度和最终草稿卡三块稳定内容，没有逐专家报告、逐 finding 或工具事件气泡。
3. 打开草稿，确认默认展示修改摘要与逐处高亮 diff，可切换完整原文/草稿；单章和多章使用一致的新增、删除和替换标记。
4. 写回后执行一次撤销，确认恢复到写回前版本；若写回后正文已再次编辑，撤销必须因版本冲突拒绝，不能覆盖新内容。
5. 使用专注执行完成一次读取、分析和固定范围草稿生成，确认非必要确认被合并；正文写回、版本冲突和未知副作用对账仍会阻断自动推进。
6. 使用后续智能视角发送编辑、读者和世界观典型请求，确认不增加分类模型调用，实际视角选择合法且可见；手动覆盖后当前任务不被系统静默改回。
7. 选择“稍后处理”后确认事项进入待改清单；当前对话立即完成的建议不先入清单，完成项自动归档。

通过标准：报告和对话密度显著收敛；减少审批不降低 diff、版本冲突、撤销和写回边界；智能视角与专注执行都不扩大用户选择范围或权限。
