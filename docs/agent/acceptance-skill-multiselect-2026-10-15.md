# 独立 Skill 多选验收

用户要求独立 Skill 可以选择多个，第二次选择不能覆盖前一次，也不能只把两个方法包装成“多选”。

## 行为

- `/` 菜单展示各独立 Skill 的选中状态；选择新项追加，点击已选项移除。
- 输入框上方逐个显示标题、设置和移除按钮，版本放在悬停提示，并提供“添加 Skill”。选择和移除不改写任务正文；删除库中一个已选对象时只清理该项，其余选择保留。
- 不对用户显式选择设置两个的数量限制。继续保留编译方法预算和模型窗口检查，超预算明确失败，不截取前两个或压缩掉方法正文。
- 创建、本轮禁用和单个文风包保持各自现有模式。选择文风包会切换到原来的包组合；本次未开放同时堆叠多个包或包与独立方法混选。
- 文风包内部主成员加至多一个辅助成员的已发布绑定保持不变，自动默认选择也保持原来的最多两个。显式多选与这些默认规则分开处理。

## 传递与执行

- 单项保留旧 `skillId/requestedRevisionId` 协议；多项通过 `entryHint.skills[]` 发送各自冻结的版本，重复 ID 或与 Pack 身份混传被拒绝。
- IntentDecision、显式 Resolver 请求、AgentPlanStep 取消两个的数量限制。ResolvedSkillSet 通过 additive `additional` 保留旧主/辅字段兼容性，并完整编译额外方法。
- Runtime 按步骤的 Operation 与 Role 匹配方法；选中的方法若无法适用于任何步骤，报告不兼容，不静默忽略。普通写作、审核及多章任务的模型节点取得该步骤所有完整冻结方法。
- 已有任务不自动改换版本。恢复保存计划时重新读取每个锁定修订，正文、约束、示例及顺序保持一致。
- 多 Skill 作为本版本起的基础能力，不设版本标记或发送前兼容拦截。服务可用即可发送完整多选请求，真实执行错误按现有失败链路呈现。
- 桌面主进程保留当前进程返回的健康元数据，确保就绪快照及重启结果包含完整能力列表；进程停止、更换或退出时清空，避免旧进程信息残留。

## 验证

- Python 原 Skill、模型方法消费、Pack 与可见范围回归：92 项通过。
- 新多选与 Intent 回归覆盖 3/4/8 个显式方法、第三项禁用、预算不足、去重、旧单项协议、多个冻结方法经过计划与模型调用、冷恢复；本次移除多选能力标记及其兼容测试。
- 桌面 Composer、删除与模型消费测试通过；消费测试确认四个完整方法及四个版本引用抵达最后的章节 provider 边界。
- Renderer/Electron TypeScript 检查通过。
- 浏览器以生产菜单和 SelectedSkillChips 验证三项同时选择、任务正文不变、选中标记、单独移除、模拟删除只移除对应选择、长标题与窄屏、深色模式。
- 无新增依赖或数据库迁移，没有修改、恢复或删除用户的真实 Skill，没有付费模型生成。对已删除群像成员的只读探测按预期返回禁用错误，没有为测试重新启用它。
