# 文风提炼：操作兼容性、证据复核与应用验收

日期：2026-10-13

后续真实 10 章运行暴露审核推理耗尽输出额度，修复及验证见 [文风证据审核输出截断修复](./acceptance-style-evidence-truncation-2026-10-13.md)。下文的 16 项为逻辑证据页；新的实际审核请求最多 8 项，确认截断后继续减半，旧成功页可复用。

## 改动目标

89 章产物虽通过格式校验，但七个 Pack Operation 均未注册，绑定与成员权限不匹配，低置信观察被写成固定规则，且缺少实际应用试写。本次修正生成链路与发布门槛，未改写真实草稿、未重读真实小说正文、未启动真实模型请求。

## 操作契约

- Python `INTENT_OPERATION_REGISTRY` 为操作 ID 来源，`scripts/export_operation_ids.py` 导出 Electron 共用的 `agentOperationIds.ts`，Python 测试验证两者一致。
- 成员 supportedOperations、规划绑定与结构化生成 schema 都使用真实注册 ID。Pack 校验逐一检查主辅成员支持的操作与 allowedRoles，拒绝重复绑定及主辅相同成员。
- Electron 编译与提交双层检查；旧 JSON Pack 不可绕过提交校验。七个历史错误别名不会自动猜测转换。
- 模型规划提示提供真实注册表；生成文档沿用同一列表，包含之前遗漏的 `novel.project_initialize`。

## LangGraph 中的文风验收

原 Toolchain 内阶段顺序：`analyze → evidence_review → plan → author → validate → quality_review → trial → compile`。结构或内容不合格走原有定向 repair，只重写受影响成员；质量修订最多两轮，仍不合格则保留工作区及诊断并报错，不交付可启用产物。其他工具链不进入该专用流程。

1. evidence_review 读取原工作单元日志，不重读整本正文。每页最多 16 个完整候选，按模型窗口限制页大小；每个 findingRef 必须恰好返回一次明确判断。引文未完整核验或无引用的候选不能升级成受支持结论。
2. 专家按稳定特征类别判断 supported/counterexample/unresolved。程序计算独立来源章数、发现数、代表引用和反例，保持真实批准范围及已分析章节数。未提及不等于不存在，支持章数不解释为原文语句频率；没有独立跨章核验就不宣称全书风格已验证。
3. 规划和成员编写使用 reviewedEvidence，而非仅八项根摘要。来源统计由程序写入；缺少至少两个独立支持章节时成员置信度低，局部独立观察不能自动变成已验证的全书高置信特征。
4. 编写后的独立内容审核检查 task_fit、rule_calibration、evidence_trace、counterexamples、contamination、binding_fit，完整通过才进入试写；unverified 不能当作通过。
5. 对同一原创中性场景分别执行基线、语言成员、悬念成员和 Pack，保存实际文本。再由独立请求对调 A/B 顺序做对照审核，检查任务完成、方法应用、可读性、非机械化及非污染。与基线完全相同或复制已有来源长句不能宣称通过。
6. 审核前与发布前仅用章节目录复核来源版本。正文或绑定改变导致工作区 inputHash 改变时，旧质量记录失效。

新 `agent.style_quality` 只承担上述受控阶段。它使用结构化结果 checkpoint、原任务的工作单元调用/Token 预算及请求 ID；重启后复用已保存结果，未知请求继续核对，不盲目重复收费。额外审核确实增加模型调用，不能宣传为免费处理。JSON Schema 校验增加 oneOf/anyOf/const 支持及封闭对象字段检查，避免阶段协议被空返回绕过。

## 草稿与发布

来自真实章节分析的文风 Pack 必须带匹配当前 authoringInputHash 的通过记录，包含成员内容检查、四份试写及三份对照审核。编译和正式保存都会检查；UI 在缺失/过期时显示“需要内容与试写审核”，格式整理不能替代质量审核。

通过记录、真实试写正文与审核摘要进入草稿产物及最终报告。结果明确限制为“原创中性场景的模型对照审核通过”，不代表所有场景都成功，也不代表完整还原来源小说。仅作品名先验的原有低置信候选路径保留，不冒称完成正文分析或实际试写。

## 内置 Skill 调整

新增 `builtin.style-skill-extractor@1.3.0`，保留 1.0.0/1.1.0/1.2.0 的原始修订供历史锁定任务读取。新版本明确：

- 完整候选分页核对及支持/反例分布；投影数、发现数与章节数区分。
- 应用已有文风方法时依据新场景/大纲生成原创正文；来源不足限制作用于新增推断，不能每次强制重新提供来源小说。
- 候选写成条件化方法，无统计依据的固定数值不能伪称来源规律；可调工程建议须显式标记。
- 真实操作/角色兼容、编写后的内容审核、实际试写与局限说明。

文档作者与规划器的产品提示同步调整，要求原创中性应用示例与失败边界。审核修订保留身份、操作与角色，允许校准被专家否定的方法和约束，不强制保留错误硬阈值。
