# 文风成员审核输入预算修复

## 真实失败原因

运行 `run_79799ff0051142c4` 的检查点停在 `quality_review`。专家阶段保存的 `maxInputBytes=48000`。这是产品阶段输入上限，报错发生在 Python 预检，不能等同于模型服务实际返回上下文窗口不足。

原始群像审核请求连同 1024 字节预留需要 **48065 字节**，超出 65 字节。组成：完整文档 16578、成员规划 4537、全部维度证据材料 23552、Pack 2061、技术语义说明 234 字节，另有容器字段与预留。前两份审核分别为 44727、43921 字节，已在原任务请求账本完成；群像请求尚未创建账本记录或发往模型。

章节分析已拆分，但后续每份成员审核重新带入全维度例证，未按审核对象组织上下文，造成下游输入超限。此问题在程序组装与报错分类，不是十章原文直接塞入同一次审核，也不是模型实际窗口已被证实不足。

## 修正与边界

- 审核先查原请求的完成结果、保存返回和未确认请求，再做新请求的输入预检。成功结果可直接复用；未确认返回先核对，不能改材料指纹后重新收费。
- 当文档审核原请求超限时，按成员维度组织代表例证；正文或规划显式引用的跨维度 feature、标签、findingRef 或完整引文，以及 `other`，也保留完整代表例证。
- **完整成员正文、规划、Pack、全部维度支持/反例/未决统计、覆盖范围和局限保留。** 仅省略无关维度的代表例证；原始证据及专家判断仍在日志。投影附完整 dossier 指纹和省略范围，不能把缺席当不存在。所有六项审核检查仍必须通过；没有例证支持的新断言不能仅凭日志指纹认定通过。
- 使用投影后的输入指纹缓存；恢复仍使用原 owner、调用额度与计费预留，不增加模型窗口、总预算或次数上限。前两份旧成功结果不改指纹、不重审。
- 无法容纳完整材料时仍在收费前终止，但使用独立 `STYLE_QUALITY_INPUT_LIMIT`，报告所需字节和阶段上限，不冒称模型实际窗口不足，也不截断正文。
- 仅迁移旧 `BUDGET_EXCEEDED` 中这条精确的文风审核预检消息，并且检查点必须是未取消、无未知写入的 `quality_review`，具有完整草稿、规划、分析引用和证据审核记录。提供“继续剩余文风审核”；总费用/工作单元预算不足、取消、未完成证据审核或其他阶段不因此开放重试。
