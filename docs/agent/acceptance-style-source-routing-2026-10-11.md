# 文风 Skill 来源路由与完成报告修复

日期：2026-10-11。

## 实机证据与原因

截图对应运行 `run_c495cd45d2d549b6`（北京时间 22:14:06–22:16:49）。只读查询显示，选中章节正文非空；所在小说有 500 个未删除章节，500 章均有内容，合计登记字数 1,086,106。正文没有因本次任务丢失。

该运行的计划输入却为 `sourceMode=named_work_model_prior`、`sourceWorkTitle=十日终焉(1-500章)`。执行事件没有正文读取调用，来源记录明确为零章正文、低置信度模型先验。

前端将当前请求“重新执行”与历史对话拼成规划目标。原规划器从整个目标中提取书名，误把历史 Agent 回复中的书名视为本轮来源请求。范围应用代码又对该模式无条件跳过已选章节范围，导致跳过正文读取。

还有一个独立的报告问题：实际 Skill 草稿 `07e4abf1-31ca-41e5-b3be-e374e01e9548` 状态为 `ready_for_review`，两个成员分别有 3,837 和 3,596 个字符的 instructions；“未编写 SKILL.md 正文 / 未生成草稿”与实际产物不符。完成报告输入压缩后主要保留了规划阶段摘要，没有明确给出后来编写完成的产物状态。报告又把小说正文草稿用的空 `draftSessionId` 当作 Skill 草稿缺失。

## 修复

- 来源识别只使用本轮请求，历史对话继续供理解任务使用，不能单独触发模型先验来源。
- 明确要求使用当前、选中或已导入样本时使用项目正文，即使请求包含书名；不把书名误解析成未找到的章节标题。
- 模型生成或注册的计划也经过相同来源规则。没有本轮明确书名来源请求时，去除误选的先验模式并应用实际范围。
- 保留明确仅按书名生成候选的路径，也保留不读取当前项目的明确请求。
- 编译后的产物摘要依据实际已编写、已校验的成员和实际来源覆盖生成；规划摘要另存为历史信息。
- 最终报告获得必需的实际产物清单，包括 Skill 草稿标识、成员数量、已编写数量和正文读取数。明确区分原作正文证据、Skill 说明正文与小说正文草稿。

不修改用户正文、历史运行或旧报告，不重新发起真实模型请求，不主动重启应用。旧任务的低置信度候选不是基于这 500 章正文的提炼结果；修复需由 Runtime 与主进程加载后生效。
