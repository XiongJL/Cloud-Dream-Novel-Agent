# Agent `/` Skill 列表加载优化

## 原因与范围

原菜单请求会刷新全部可见 Skill 的完整注册表，逐个跨进程读取正文，再加载 Pack 与默认设置。前端多个 effect 还会重复触发，章节与选区变化也会导致列表重读。

本次只调整索引读取和缓存，不增加模型调用、依赖、数据库字段或迁移。

## 实现

- `agent.skills` 使用现有原生 `agent_skill.list` 的元数据构建公开索引，校验身份、能力、角色与版本；不读取正文或绑定，不修改任务注册表。内置 Skill 在桥接不可用时仍保留。
- 原生单 Skill 列表使用两次批量查询，版本查询只选索引字段。Pack 列表使用四次批量查询，复用现有 Pack 的作用域、成员、路由与哈希校验，不选成员正文。
- 前端按小说、语言和 Pack 能力区分缓存，合并同一键的并发加载，成功列表缓存 10 秒；三类索引请求并发执行。章节、选区和正文不参与列表请求。
- 重试、发布、范围变更与默认设置变更立即清空所有小说的列表缓存。失效前的旧请求不能覆盖新缓存；失败或部分失败不缓存。
- 规划与预览负责加载完整注册表，每次读取当前元数据，只有版本 ID、哈希、manifest、版本号和定义都未变更时复用已加载正文。刷新原子提交，并与范围变更串行协调。
- 已启动任务依旧按锁定版本编译；执行前的可见范围校验和 Pack 默认绑定语义保留。菜单展示不是执行授权。

## 验证

- 新增 Python 索引专项：只读元数据、菜单不改变注册表、预览消费完整正文、相同版本复用、新版本重载、移除后不保留、能力校验，以及未打开菜单也能规划并调用用户 Skill。
- Python Skill、Pack 选择、正文消费与范围回归 95 项通过；新增直接规划场景和执行版本专项 15 项通过（分组去重合计 107 项）。
- 原生范围测试同时断言：单 Skill 索引 2 次查询，Pack 索引 4 次查询，多 Pack 不增加逐成员查询，索引 SQL 不包含正文列。
- 原生 Store、范围修改、独立副本、历史默认绑定、正文消费、Composer、Chat 上下文回归通过。
- 前端缓存专项覆盖并发去重、TTL、跨小说隔离、范围变更与旧请求竞态、失败重试、部分失败及全缓存清理。
- Renderer 与 Electron TypeScript 检查通过。

## 实测边界

未重启正在使用的应用，未调用付费模型，未修改用户真实数据。查询次数和正文不读取由隔离数据库测试验证；实际点击耗时需应用重新加载新代码后确认。首次 Runtime 启动仍可能有启动等待。
