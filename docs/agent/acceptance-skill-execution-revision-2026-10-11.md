# Skill 自适应执行修订验收

日期：2026-10-11。对应 [Review 修订设计](./skill-adaptive-execution-revision-2026-10-10.md)。

## 已实现的边界

一个原业务任务仍是一个计划步骤。LangGraph 子图只负责该任务的来源分析，独立单元最多三个并发；需要前序状态时顺序执行，要求全局依赖的通用任务回到原业务路径。

当前通用适配覆盖 `editor.range_review`、`writer.range_revision_plan`、`worldbuilding.range_consistency`。自建 Skill 的锁定方法进入路由、每个分析单元、汇总和原业务专家请求；分析结束后继续原 RAG、专家审核、normalizer 和结构化产物发布，不提前结束父任务。最终保留 `metadata.expertReport` 和角色专属数据，原有采纳、拒绝、暂缓、待改清单继续使用原契约。发布失败允许恢复，复用专家缓存与已有产物 ID。

内置文风提炼仍使用可信注册表绑定的专用链路；Pack 规划阶段明确承担文风专家核验职责，再生成成员文档并编译、提交用户审核。用户同名 Skill 不获得内置 authoring 权限。没有执行提示的通用 Skill 继续走标准业务链路。

## 分析材料与专家审核

`skillAnalysis.version=2` 使用 `analysisRef`、`unitRefs`、覆盖、执行策略和有界摘要。完整单元结果与证据保存在 `agent_skill_units.db`；原文不进入图检查点。专家适配器从全部叶单元建立稳定候选引用，按实际序列化容量和每页最多 16 个候选分页，要求每个候选都有确认、排除或未决决定。

人物、世界观、物品、地图、情节与叙事摘要通过 `expert_context` 读取，原有上下文构建复用同一资料查询。分析文字没有写入 `chapters.content` 冒充原文。专家引用只能匹配获准短证据；伪造引用被移除并产生警告及不确定性。实际读取的正文哈希、版本、时间与 Unicode 字符偏移写入证据记录；专家审核前和发布前再次核对章节版本。

根汇总最多 8 条发现只承担导航，不替代完整候选集合。跨页重复问题采用稳定问题 ID，保留较高严重程度和证据并集。单元发生发现容量溢出时，警告传播到父结果，不能宣称穷尽全部问题。

覆盖区分“原文分析 N/总章数”和“专家审核材料 M/总章数”。专家没有在该阶段复读全文；分页结论不自动成为全书整体评分，多页时全局及维度分数留空并解释原因。跨章因果、悬念兑现或语义冲突仍需要相应连续状态和证据，局部并行不能证明这些维度。

## 预算和恢复

默认配置最大输出为 32,768；每次实际调用采用 route / analyze / merge / expert 阶段预算，结合模型窗口、锁定方法和用户设置预留输入及输出。初次输出、截断恢复、结构化修复共享单元调用租约；收费派发前再次检查完整受保护请求与 schema 的实际窗口。

完整结果与汇总投影分离，二路汇总只读取有界发现及证据引用，引用必须还原为已核验材料。6KB 汇总窗口可以处理两个各超过 8KB 的完整结果。长章按 Unicode 字符与 JSON 容量切分，顺序状态先占预算；不截断原文。首次路由前检查最小投影、章节调用、汇总、路由和专家页的最低可行性。

各单元及通用专家页共享原子总预算账本。并发前预留内部恢复可能的调用，全部 usage 已知才按实际 Token 结算；未知 usage 保留保守预留。长章实际片段数和专家实际分页数在得到材料后逐次检查，不能承诺目录阶段已精确预估所有费用。达到预算时明确停止并保留已完成结果。

收费请求先在父状态保存稳定 request ID、结果引用、输入指纹和 prepared 状态，再调用现有 Automation checkpoint。恢复优先使用保存结果完成本地处理；prepared 或传输未知不能作为“尚未收费”的证明。同一父任务有未核对请求时，变更执行策略也不能绕过阻断。专家或发布失败不会重做已完成原文分析。

## 存储隔离与版本

Runtime 构造不打开 Skill 数据库；首次自适应调用通过异步锁、后台线程懒初始化。单元操作和图运行分别关闭自己的数据库连接，无需常驻连接或新增应用退出钩子。

图检查点单独损坏时保存数据库及存在的 WAL/SHM 诊断副本，重建调度并复用完整单元结果。请求账本损坏时保留文件，当前自适应任务报告 `recovery_required`；不清空账本、不自动整批重发。普通未拆分任务仍能运行。权限、磁盘和锁等待失败只影响当前阶段，SQLite 等待上限为一秒；没有添加无限存储重试。

`executionHints.version=1` 是可选方法提示，不能配置权限、内置身份或并发上限；新增不兼容语义需要新的 schema。执行策略和材料分别使用 v2，策略、来源、方法及执行器版本参与缓存指纹。依赖保持 `langgraph==1.2.8`、`langgraph-checkpoint-sqlite==3.1.0`，本轮没有引入 LangChain。

## 仍然保留的限制

- 当前不迁移旧开发版本的自建文风 Skill；未来依赖升级必须通过契约及恢复测试，不能自动保证任意未来依赖兼容。
- 本轮统一总预算覆盖自适应只读分析及三个通用业务的专家页。内置 Pack 规划、成员文档生成继续使用各自现有任务输出预算，没有声称已纳入同一本全链路费用账本。
- 账本损坏时提供隔离和诊断，不自动完成跨库修复。未核对请求需要可靠的现有请求记录；保留中间材料不会证明供应商收费幂等。
- 完整候选、专家决定与结果引用已保存；没有添加自动过期删除。执行缓存仍不进入作品备份，进行中/未知记录不会被自动清理。
- 尚未用真实收费模型执行 500 章整本小说验收；当前证据是模型替身、契约测试与真实编排/存储测试。
