# Skill 可见范围设置：创建与后续修改

日期：2026-10-13。状态：已实施，实际边界与验收见[实施记录](./acceptance-skill-visibility-2026-10-14.md)。本方案替代此前误解为“全局默认调用”的设计。

## 1. 用户需求

创建 Skill 时默认归属于当前小说，也可以主动选择“所有小说可见”，创建后允许修改。所有小说可见表示保存到当前用户的个人技能库，切换任何小说都可找到并选择该 Skill；不自动设置运行默认、不自动绑定所有小说。

同时适用于普通单 Skill 和文风提炼生成的 Skill Pack。整包与它新创建的成员采用同一可见范围。

## 2. 已有能力和当前缺口

现有存储已经具备所需模型：

| 用户界面 | 存储 | 可见规则 |
| --- | --- | --- |
| 所有小说可见 | `scope: user`，`ownerNovelId: null` | 各小说都展示在“我的技能库” |
| 仅当前小说可见 | `scope: novel`，`ownerNovelId: 当前小说 ID` | 只在对应小说展示 |

`AgentSkillStore.listSkills/listPacks` 已使用上述过滤规则，提交 Pack 时也会统一保存包和成员的范围。因此不新增全局默认表、不修改默认优先级、不增加模型调用、不升级 LangGraph/LangChain。

主要缺口在输入与流程传递：

- 普通创建入口目前根据请求文本是否包含“当前小说”等词推测 `scope`，否则使用 `user`。用户缺少明确控件。
- 文风提炼链路目前根据是否存在小说 ID 选择 `novel/user`；选定小说正文分析时会生成小说专属产物，缺少独立的产物可见范围设置。
- 草稿预览只显示“当前小说专属/我的技能库”，没有清楚表达创建时的选择与最终结果。

需要区分“用哪本小说作为分析来源”和“生成 Skill 对哪些小说可见”。来源是当前小说，不要求产物也仅属于当前小说。

## 3. 界面设计

用户选择“创建 Skill”或“文风 Skill Pack 提炼”入口后，输入区显示“保存范围”选项：

- **所有小说可见**：保存到我的技能库，可在其他小说中选择使用。
- **仅当前小说可见**：只在当前小说中展示和使用。

已有小说时两项可选；没有当前小说时提示先选择小说，或由用户显式选择“所有小说可见”后创建，不自动扩大可见范围。选择小说专属后切换小说，清除该次创建配置或重新绑定当前小说并要求用户重新选择，不能悄悄沿用另一本书的身份。

普通单 Skill 与文风 Skill Pack 的新创建入口统一默认“仅当前小说可见”，提交时明确传入当前小说身份；用户可以在发起生成前显式切换为“所有小说可见”。这是新版创建入口的默认行为调整，旧请求和旧产物仍按兼容规则处理。控件始终可见，因此不需要用户掌握特定关键词。

提炼界面将“原文范围：已选 10 章”等已有控件与“保存范围”并列展示，两者独立。计划卡、草稿审核卡和保存成功提示均展示最终可见范围。所有小说可见的包与成员在其他小说的 `/` 菜单中归入个人技能库，仍通过已有入口手动选择。

创建入口选择初始范围。草稿审核卡及保存后的 Skill/Pack 详情均提供“可见范围”设置；已发布产物可直接修改范围，默认保持同一个 Skill/Pack ID，不要求用户重新生成或另存。内置 Skill 的范围只读。

发布后界面使用“所有小说 / 指定小说”两个选项，避免离开来源小说后“当前小说”含义不清。选择指定小说时显式显示目标小说选择器，默认预选当前打开的小说，提交前显示小说名称；来源小说不会被自动当作目标归属。

### 无独立管理页时的具体入口

首版复用 `/` 选择菜单与检查器产物卡的入口，不先增加独立管理页面。菜单每行展示名称、简短用途、可见范围和版本；右侧添加常驻 `⋯` 按钮，触屏、键盘用户也可发现，不仅悬停时才出现。

- 点击条目主体或按 Enter：选择本次使用并关闭菜单，沿用原有行为。
- 点击右侧 `⋯`：只打开该条目的操作菜单，含“查看详情”“设置可见范围”；不选择 Skill、不发送消息、不改默认。
- “查看详情”：在同一轻量弹窗复用 Markdown 阅读组件展示当前已发布 Skill/Pack，不把历史草稿当作最新配置；检查器产物卡也调用该弹窗。
- “设置可见范围”：打开一个小型设置对话框，显示目标名称、指定小说/所有小说选项、归属小说和实际影响。Pack 显示“包及 N 个成员一起修改”。保存成功刷新 `/` 的分组和详情；失败保留编辑选择并展示具体原因。
- 内置 Skill 提供查看详情，其范围为只读；包成员的范围入口显示“由文风包管理”，转到所属包，避免独立修改。
- 已保存产物卡和已选 Skill 标签的 `⋯` 复用同一设置对话框，用户不必每次重新输入 `/`。

将“选择使用”和“管理设置”作为两个独立操作，参考 VS Code 的 Quick Pick 项级按钮模式：[官方 API](https://code.visualstudio.com/api/references/vscode-api#QuickPickItem)。这不是把整个 `/` 菜单变成管理页面：正文编辑、版本记录仍在详情中完成，选择菜单只保留两个轻量入口。

键盘仍由上下方向键选择条目、Enter 使用；Tab 可访问行操作按钮，Esc 优先关闭操作菜单或设置对话框，回到原来的查询与选中条目。不要把 `⋯` 嵌套在已有行 button 内；现有 `listbox` 语义也需随双操作结构检查，确保屏幕阅读器能区分选择与设置。

缩小范围后对象不再属于当前小说时，从该小说菜单移除，并提示归属小说；切换到目标小说后仍可管理。列表加载正常但对象不可用时，允许进入详情查看原因，不能因为“使用”按钮禁用而一起禁用管理入口。将来出现停用恢复、批量管理等需求，再增加技能库面板，不在本次先造完整管理页。

## 4. 参数与执行链路

普通单 Skill 继续使用已有 `AgentSkillAuthorRequest.scope`，UI 的范围选择替代当前文本关键词推测；没有主动切换时明确传 `scope: novel` 及当前小说 ID。旧调用未提供范围时保留已有语义。

文风提炼新增可选产物参数 `publicationScope: user | novel`：

1. Composer 的结构化创建配置传到请求；不让模型从正文内容推测可见范围。
2. Intent/Plan 将明确值写入 `agent_skill.style_extract` 的输入，保持模型生成计划时不丢失该值。
3. 原文来源仍使用 `novelId`、章节选择等现有字段，`scopeId` 继续表示原文分析范围，不挪作产物范围。
4. Runtime 在起草 Pack、生成每个成员的托管头、建立 Native 工作区时使用同一最终范围；来源小说保留到 `sourceNovelId` 及证据记录。
5. Native 提交按草稿范围创建 Skill/Pack；`user` 的所有权字段必须为空，`novel` 必须匹配声明的所属小说。

未提供新参数的旧请求、旧检查点继续采用“存在小说则小说专属，否则个人库”的逻辑。不要给旧序列化输入无条件补字段，从而改变已有缓存指纹和恢复键；新参数仅在显式设置时进入新任务输入与指纹。

生成计划中的分析输入与初始范围在确认前冻结，执行、失败重试和检查点恢复不从当前 UI 偷换输入。用户后续明确修改的最终发布范围属于独立版本化设置，按第 6 节处理；实际发布时草稿、包和成员必须统一到该最终范围。

## 5. 校验与兼容

- `novel` 需要有效小说身份；`user` 可保留来源小说作为证据，但不能设置 `ownerNovelId`。
- 包和新增成员必须同范围；个人包不允许新建时引用小说专属成员导致其他小说看到不可用包。
- 参数、托管头、草稿元数据冲突时明确报错，不偷偷改写用户选择。
- 已有 Skill 的内容编辑与可见范围修改分开；范围修改保留身份、方法 Revision 和正文哈希，独立增加范围配置版本。
- 发布校验、文风证据审核与试写门禁保持原有要求。`scope: user` 不意味着跳过方法适用性或证据质量检查。
- 可跨小说使用的是提炼后的写作方法，来源证据仍可追溯；不把原小说的人物、设定或剧情自动注入目标小说。
- 已发布的小说专属 Skill、旧包、旧默认绑定和运行快照不自动批量升级范围，仅在用户选择具体产物后修改。
- 现有备份已包含 Skill、Pack、成员和来源字段；新增范围版本字段需同步更新初始化、升级和备份兼容规则，旧数据按初始版本读取。不为此新增全局默认表。

## 6. 后续切换规则

| 修改 | 效果 | 引用处理 |
| --- | --- | --- |
| 小说 A → 所有小说 | 扩大可见范围，保留 ID、正文与来源 A | A 的默认与绑定保留，不自动添加其他小说默认 |
| 所有小说 → 指定小说 A | 仅 A 可在新任务中选择 | 保留 A 的设置，清理其他小说的新任务默认和绑定 |
| 小说 A → 小说 B | 修改归属，来源证据仍可来自 A | 清理 A 的新任务设置，不自动替 B 设置默认 |

范围扩大直接保存并提示结果；缩小或转移先展示影响预览。例如：“仅《小说 A》可见；将取消其他 2 本小说的默认引用，已有运行任务继续使用原版本。”用户通过该预览中的“确认修改”提交，不另外添加重复确认。

清理只是取消关联，不删除任何 Skill 正文或历史产物。本书默认偏好采用已有取消墓碑及递增版本，避免旧绑定复活。若无默认使用，预览明确显示无关联影响。重复设置成相同范围是幂等操作，不重复清理。

### Pack 与成员

新生成的 Pack 和成员作为一组修改，Native 一个事务完成范围、归属和关联清理，不能只修改包让成员在其他小说不可用。成员详情显示“由文风包 X 管理”，范围入口转到包设置，避免用户分别改出不一致状态。

旧成员若被多个包共享，预览列出依赖，禁止直接收窄导致其他包失效。提供“为这个包建立独立成员副本再修改范围”的显式方案；不级联修改用户没有选择的其他包。副本保留方法内容及审核来源，新成员引用产生新 Pack Revision，不覆盖旧 Revision；内容没有变化不重新调用生成模型，但必须通过 Native 的来源和结构校验。

### 草稿与生成中任务

未开始生成时直接修改创建配置。已生成草稿使用 `expectedDraftVersion` 检查冲突，同步草稿范围和成员托管头，重新做格式/元数据一致性检查；方法正文不变时保留适用的内容审核记录，不能不经校验就把总体验收状态设为通过。

生成中的输入范围保持冻结；允许用户设置最终发布范围，作为独立草稿发布设置在安全落盘点应用。界面显示“保存时将对所有小说可见”等目标状态，不修改原文分析来源、模型请求或检查点输入。生成失败后该发布设置仍保留，恢复继续读取原分析输入，发布时再应用最终范围。实现中不要把未应用的发布设置展示为已生效。

### 计划、运行与恢复

已经启动的 Run 及其失败重试保留精确正文、成员引用和启动时的可见范围授权；本次范围修改不强制停止它们。未启动的计划执行前重新检查当前可见范围，若已不适用，提示“Skill 可见范围已变更，请重新选择”，不能作为新任务继续跨小说使用。

当前 `skillSnapshot` 主要保存版本引用，尚不足以单独证明启动时的小说范围。需要新增由 Runtime 在启动时生成并持久化的范围快照，记录 Run/Novel/Skill/Pack/Revision 和范围配置版本；恢复走已启动任务的快照读取路径，不能通过客户端任意传入 Skill ID 绕过范围校验。旧任务快照缺少新信息时，从服务端保存的原计划、Run 上下文及原成员记录核对，无法核对则明确提示，不能直接授予跨小说读取。

所有新选择接口、列表、预览、默认解析和 execute-plan 检查同一范围权威。变更完成清理 Runtime 的当前注册表缓存并通知 UI 刷新，确保新任务不会继续使用旧列表；历史执行所需的数据通过独立精确快照路径加载。

### API 与一致性

增加统一 `agent.skill.visibility.preview/set`，参数包括 `targetType: skill|pack`、目标 ID、`scope: user|novel`、目标 `ownerNovelId`、`expectedVisibilityVersion`；草稿使用独立草稿版本。修改接口仅向用户 UI 开放，不加入模型工具权限。

Skill 和 Pack 定义增加 `visibilityVersion`。Native 在事务里重新校验目标版本、范围、依赖包、默认及绑定影响；依赖集合与预览不一致时返回冲突并要求重新预览，不能用过期预览清理新出现的关联。相同范围内 stableId 冲突明确报错并提供改名/独立副本入口，不自动合并或覆盖现有对象。

修改 scope/ownerNovelId 不创建方法 Revision：当前编译正文与 manifest 的哈希不包含它们，Pack 的绑定哈希也无需因纯范围变更而改写。历史草稿托管头保留当时范围；当前详情与导出由最新定义元数据生成范围头，明确区分“创建时范围”和“当前可见范围”，不能把旧头作为当前权限依据。

## 7. 实施位置与验证

主要改动：创建入口配置、草稿/已发布详情的范围设置、Intent/Toolchain 输入与文风起草范围传递；Native 范围事务、依赖预览、配置版本及绑定清理；Runtime 新任务范围校验、注册缓存刷新和运行范围快照；数据库升级与备份兼容。

保留本书默认的正常设置规则、Pack 原子成员解析、单步两个成员限制和普通写作页 AI 调用；仅在用户缩小范围使引用不再适用时清理相应默认关联。

验收使用隔离数据库和模拟模型，覆盖：

1. 在小说 A 创建“所有小说可见”的单 Skill 与 Pack，在 A/B 的列表及 `/` 菜单都能选择；成员范围与包一致。
2. 在小说 A 创建“仅当前小说可见”的产物，小说 B 不展示且显式跨小说引用被拒绝。
3. 取小说 A 的正文生成个人包，保留 A 的证据来源，但包及成员的 `ownerNovelId` 均为空。
4. 单 Skill 与 Pack 新入口均默认当前小说；没有小说时需先选择小说或显式选择个人范围，不自动转为所有小说可见。
5. 参数丢失、范围冲突、切换小说、重试与恢复不造成所属范围漂移。
6. 旧请求、旧检查点、旧默认、发布门禁和备份回归通过。
7. 发布“所有小说可见”产物不会增加任何小说的默认绑定，也不触发额外模型请求。
8. 三种后续切换均正确处理新任务可见性、默认及绑定，保留正文 Revision/Hash；重复设置幂等，过期配置和过期影响预览被拒绝。
9. Pack 与成员一并切换；共享成员不破坏其他包，独立副本保留原引用和审核来源。
10. 已启动任务跨范围变更后可按真实快照恢复，未启动计划与新任务不能绕过当前范围；伪造快照被拒绝。
11. 草稿与生成中发布范围设置不重跑正文分析，不修改旧检查点指纹；完成后托管头与实际定义一致。
12. 范围改动的缓存刷新、stableId 冲突、归属小说删除及备份恢复保持一致。
