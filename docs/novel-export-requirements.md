# 小说导出需求与设计

版本：v0.4
日期：2026-10-19
状态：已实现，验证结果与环境限制见[首版验收记录](./novel-export-acceptance.md)
适用范围：桌面端选定作品的整本、章节范围和分批导出，包含作品信息和正文。

## 1. 目标与首版范围

作者可以从首页选中作品的操作区，或编辑页顶部选择“导出小说”，导出整本、指定章节范围，或按每 N 章拆成多个 TXT / DOCX 文件。导出必须包含最后一次编辑，不能因为自动保存延迟、刚切换章节或只加载了部分章节而遗漏内容。分批用于控制单个 DOCX 的内容量，降低后续阅读软件处理单个长文档的负担；不承诺任意大小文件的打开速度。

首版确定以下范围：

| 项目 | 首版要求 |
| --- | --- |
| 作品范围 | 首页当前选中的作品，或编辑页当前打开的作品；每次一部 |
| 内容范围 | 书名、作者、作品简介，然后是卷名、章节标题和已正式保存的正文 |
| 排列方式 | 按作品目录的卷、章顺序排列，不按创建时间或最近编辑时间排列 |
| 文件格式 | TXT、DOCX；整本/指定范围生成一个文件，自动分批每 N 章一份，默认 500 章 |
| DOCX 结构 | 书名样式、卷一级标题、章二级标题、正文段落、可点击目录 |
| 数据一致性 | 保存并等待待提交编辑完成后，读取同一份作品快照生成文件 |
| 产品入口 | 首页作品操作区 / 编辑页顶部 → 导出小说 → 选择格式与范围 → 选择保存位置 |
| 运行方式 | 本机离线完成，优先由独立 Python Worker 生成文件，无需模型、网络或启动 Agent 会话 |

本文定义首版产品和实现契约，实际验证范围以验收记录为准。

## 2. 不纳入首版的内容

- 任意勾选不连续章节、单独按卷选择、批量导出多部作品。连续章节范围及按章节数拆分文件已纳入当前范围。
- PDF、EPUB、Markdown、HTML 等其他格式。
- 封面图片、大纲、角色、物品、世界观、地图、灵感、评论、情节锚点信息、Agent 会话及未应用草稿。作者和简介属于首版必需内容。
- 自定义排版模板、字体选项、页眉页脚、封面设计、出版级排版或所见即所得复刻。
- 导出前自动润色、纠错、补全空章、重排章号或改写正文。
- 云端导出、后台任务中心、定时导出及文件分享。

正文导出与现有 `.nebak` 完整备份分开：正文文件用于阅读和交稿，不能用于完整恢复作品资料。保留现有备份入口与用途。

## 3. 入口与交互

### 3.1 首页和编辑页共用导出入口

两处均为直接入口，共用同一导出流程，不单独新增作品菜单。

| 位置 | 具体入口 | 目标作品 |
| --- | --- | --- |
| 首页 | 当前作品信息下方，现有“继续写作 / 新建 / 导入 / 编辑作品”操作区增加次级按钮“导出小说”，靠近“编辑作品”；窄屏允许换行 | 点击时选中的 `activeNovel.id` |
| 编辑页 | 顶部右侧，现有设置按钮左侧增加“导出小说”按钮；窄屏可用带提示和无障碍名称的图标按钮 | 当前 `novelId` |

- 首页是管理作品时的主入口，无需打开章节即可导出；编辑页入口方便写作中直接导出。
- 两处共用一个格式弹窗、保存流程、进度与结果组件，以及同一主进程导出服务，不维护两套实现。
- 写作模式和 Agent 模式共用编辑页顶部入口，不依赖当前章是否打开或目录是否展开。
- 点击后冻结目标作品 ID，格式弹窗始终展示该书名；不能因为首页轮播选择变化而导出另一部作品。
- 首页作品信息正在编辑时，不提供并行导出操作；先通过现有保存流程保存作者和简介，再导出，避免把尚未提交的表单误认为已导出。
- 未加载作品、作品已被删除时不可启动。相同窗口已有导出任务时禁用重复启动；后端校验重复请求。
- 入口和格式弹窗支持键盘操作、焦点恢复及现有深浅主题。

首版不另建作品菜单，也不迁移现有操作。后续如作品级动作增多，可考虑以“作品”菜单收纳“作品信息（书名、作者、简介）”“编号设置”“导出整本”等；新建、导入和删除不因本次需求调整位置，这些未来菜单整理不属于首版实现范围。

### 3.2 格式弹窗

弹窗标题为“导出小说”，显示当前书名、格式选择和导出范围。章节数量通过有效卷章统计接口读取，仅作当前参考，最终以保存后的快照为准。

| 控件 | 行为 |
| --- | --- |
| TXT | 默认选中，说明“纯文本，包含作品信息、卷章标题和正文段落” |
| DOCX | 说明“Word 文档，包含作品信息、标题层级和目录” |
| 取消 | 关闭弹窗，不启动导出 |
| 选择保存位置 | 确认格式，打开系统保存对话框 |

导出范围提供三个互斥选项：

| 选项 | 行为 |
| --- | --- |
| 整本单文件 | 默认；全部有效卷章写入同一个文件 |
| 指定章节范围 | 输入开始、结束序号，例如 1–500；生成一个文件 |
| 按章节数分成多个文件 | 输入每份章节数，默认 500；显示预计文件数，自动处理全书 |

范围按跨卷的全书目录位置从 1 计数，包含空章，不使用可能重复的卷内显示章号。开始、结束、每份数量必须为正整数，开始不能大于结束，结束不能超出最新快照中的章节数量。空作品只支持整本单文件。DOCX 默认包含目录，首版不提供排版配置。

### 3.3 保存位置

- 由 Electron Main 打开系统保存对话框，默认文件名为 `<书名>.txt` 或 `<书名>.docx`。
- 指定范围默认文件名带 `_第1-500章` 后缀。自动分批改为选择保存目录，并在其中创建独立的新文件夹；文件名带全书位置范围，例如 `<书名>_第0001-0500章.docx`。范围数字按总章数补零，使字典排序也符合阅读顺序。
- 自动分批不会覆盖已有文件夹：先在同目录临时文件夹内生成全部文件，全部验证成功后一次提交新文件夹。第二份或后续任一份失败时，不交付半套文件，原有导出保留。
- 文件名清理系统不允许的字符、保留设备名、末尾空格及句点，并限制长度；清理后为空时使用“未命名作品”。文件名清理不改变文档内书名。
- 过滤器限定选中的格式；无扩展名时补齐，其他扩展名需要更正或提示，不能生成内容与扩展名不符的文件。
- 若扩展名规范化改变了最终目标，覆盖检查必须针对最终路径执行。
- 目标已存在时沿用系统覆盖确认；用户取消覆盖或取消保存对话框均视为正常取消，不提示失败、不生成文件。
- 选择位置期间可继续编辑；最终点击保存后进入“保存编辑内容”阶段，此后确定本次导出边界。

### 3.4 进度与结果

顺序为：

```text
选择格式 → 选择保存位置 → 保存编辑内容 → 读取作品快照
                                      → 生成文件 → 写入完成 → 成功提示
```

- 显示当前阶段；逐章转换时可显示“已处理 X / Y 章”，没有可计算总量时使用处理中状态。
- 自动分批同时显示“第 X / Y 份”及已处理的总章节数；各份依次生成，每份使用独立 Python Worker，避免在同一 DOCX 文档树中累积全书内容。
- 保存与快照阶段短暂禁止当前作品的正文输入、切章和目录修改，避免捕获边界变化；快照取得后恢复操作，后续编辑不纳入本次文件。
- 文件生成和写入期间，界面保持响应；重复点击不能启动第二个相同任务。
- 首版支持在格式弹窗和系统保存对话框取消；开始保存后不提供任务取消按钮，显示“正在导出，请稍候”。发生错误必须退出忙碌状态并允许重试。
- 成功提示“已导出《书名》”，展示文件名和位置，提供“打开所在文件夹”。只有文件完整提交成功后才提示成功。
- 失败提示明确发生在保存、读取、转换还是写入阶段；保留作者编辑和格式选择，允许重新选择位置后重试。

## 4. 内容与顺序规则

### 4.1 数据边界

- 从本地数据库读取本次目标 `novelId` 对应的作品、卷和章节，不能直接拼接侧栏缓存或当前打开的正文。
- 排除软删除的作品、卷和章节；卷删除后，其下章节即使未单独标记删除也不导出。
- 包含已应用并正式写回章节的 Agent 内容；未应用的草稿和候选内容不导出。
- 没有当前章时仍可导出整本作品。没有章节或所有章节正文为空时也允许导出，保留实际存在的书名与卷章结构，完成提示说明“无正文内容”。
- 空卷保留卷标题；空章保留章节标题，正文为空，不插入占位文字。
- 作品不存在、卷章关系异常或无法完整读取时，停止导出，不能跳过异常章节后报告整本成功。

### 4.2 顺序与标题

整份文件先输出作品信息，再输出正文：TXT 为“书名 → 作者 → 简介 → 各卷各章正文”；DOCX 为“书名 → 作者 → 简介 → 目录 → 各卷各章正文”。

作品信息规则：

- 书名取 `Novel.title`；作者沿用首页现有读取规则，取 `Novel.formatting` JSON 中的 `author`；简介取 `Novel.description`，无需新建作者字段或表。
- 作者显示为“作者：<已保存作者名>”；简介以独立“作品简介”标签及原简介段落显示，保留多段文本。
- 作者或简介为空时省略对应项及标签，不生成“佚名”“暂无简介”等占位内容，也不把首页显示用的默认说明写入文件。
- 首版作品信息包括书名、作者、简介；不额外加入创建时间、修改时间、字数、封面或内部 ID。
- 作品信息与正文必须来自同一快照；元数据读取不依赖页面上次加载的缓存。

1. 卷按 `Volume.order` 升序排列，卷内章节按 `Chapter.order` 升序排列。
2. 若历史数据出现相同 `order`，使用 `createdAt`、`id` 作为稳定的次级顺序；读取、快照和渲染使用同一排序规则，结果可重复。
3. 卷章标题遵循当前目录的编号模板：使用 `Novel.formatting` 中的 `volume`、`chapter`，默认分别为 `第 {n} 卷`、`第 {n} 章`；编号使用记录的 `order`，不在导出时重新连续编号。
4. 标题由“格式化编号 + 一个空格 + 已保存标题”组成；标题为空时仅输出编号。历史标题若已经带有完全相同的格式化编号前缀，只保留一次，不对其他文字做模糊删改。
5. 编号配置缺失或无效时使用默认模板，不因此阻止正文导出。
6. 相同名称的卷或章节分别保留；DOCX 内部链接使用记录 ID 生成的唯一书签，不能按标题去重。
7. 正文中即使重复写了章节标题，也作为正文原样保留，不做标题识别或自动删除。

### 4.3 正文转换

正文存储存在 Lexical JSON 与历史纯文本两种形态。必须复用 `apps/desktop/shared/lexicalDocument.ts` 现有公共解析和文本转换能力，在公共模块内补齐导出需要的保留空白、段落结构和 Mention 名称支持，再将统一段落数据交给 Python 渲染 TXT、DOCX；不在导出服务或 Python 内另写一份 Lexical 解析器。

| 内容 | 输出规则 |
| --- | --- |
| 普通文本 | 保留文字、标点、中文、英文、Emoji、全角空格及有意义的空白 |
| 段落与空段落 | 保留顺序和空段落，不将整章压成一行或统一压缩空行 |
| 段内换行 | 保留为 TXT 换行、DOCX 段内换行，与段落边界区分 |
| 角色/物品等 Mention 节点 | 输出节点中保存的可见名称 `mentionName`，不导出 ID、胶囊界面或链接 |
| 灵感标记、情节锚点 | 保留包裹的正文文字，移除标记元数据与装饰 |
| 粗体、斜体、颜色等行内样式 | 首版统一输出正文样式，保留文字即可 |
| 历史纯文本 | 保留文字、段落、空行和缩进；统一识别 CRLF / LF / CR 换行 |
| 明确无法解析的结构化正文 | 阻止导出并显示卷章定位，不能输出原始 JSON 或静默当作空章 |
| 未知节点 | 可完整遍历子文本时保留文字；无法确定可见内容时报告不支持的章节，不能静默漏字 |

空字符串和合法空 Lexical 文档都是正常空章。纯文本可以以 `{` 开头或本身是 JSON，不能仅凭首字符或 `JSON.parse` 成败认定为损坏；实现需明确区分受支持的 Lexical 文档、历史纯文本与已确认损坏的结构化内容，并覆盖相应样本。

所有转换仅用于导出，不回写章节、不改变字数和版本。TXT 与 DOCX 应共享同一份段落数据，保证正文一致。

### 4.4 范围与分批的内容规则

- 三种模式均使用一次保存屏障后的同一作品快照，分批期间不重新读取数据库。继续写作产生的修改不混入后续批次。
- 指定范围和分批文件只包含选中章节所在的卷；卷标题、章节标题和原显示编号保留，不因截取范围重新编号。空卷仅在整本单文件模式保留。
- 每一份独立包含书名、非空作者、简介；DOCX 包含本份卷章的标题层级和目录，可以单独阅读。
- 章节不可拆开；默认 500 章是控制文件体量的产品默认值，不是 Word/WPS 的性能保证。单章过长时可选择更小的批次。
- 当前实现仍在 Electron 中读取完整原始快照，但每次只转换当前批次并传给 Python。分批控制单个文档和 Python 文档树大小，尚不等于完整数据库读取链路已流式化。

## 5. TXT 文件规范

- 编码固定为 UTF-8（带 BOM），便于常见 Windows 文本工具识别中文。
- 输出换行固定为 CRLF，不随运行设备改变。
- 文件顺序：书名 → 作者 → 作品简介 → 各卷标题 → 该卷各章标题与正文；空作者或空简介按第 4.2 节省略。
- 书名、作者、简介标签、卷标题、章节标题作为独立行，相邻结构块之间插入一个空行；简介和正文内部的空行、缩进按原内容保留。结构分隔不用于裁剪原有空白。
- 不额外输出文本目录、页码、统计、导出时间或软件宣传信息。
- 文件末尾保证有换行，已有正文末尾空行不删除。

示例（编号按作品配置生成）：

```text
长夜行舟

作者：行舟

作品简介

一个雨夜，旧江湖的故事重新开始。

第 1 卷 初入江湖

第 1 章 雨夜

雨落在石阶上。
他推开了门。

第 2 章 故人

灯下坐着一个人。
```

## 6. DOCX 文件规范

### 6.1 文档结构与默认排版

| 元素 | 要求 |
| --- | --- |
| 书名 | 文档开头，使用 Title 样式，不进入卷章目录 |
| 作者 | 书名之后，普通作品信息样式，不进入目录 |
| 作品简介 | 作者之后，独立标签与简介段落，保留多段结构，不进入卷章目录 |
| 目录 | 作品信息之后、正文之前，独立“目录”标签，不将自身纳入目录 |
| 卷名 | Word 内置 Heading 1 / 标题 1，带正确大纲级别 |
| 章节标题 | Word 内置 Heading 2 / 标题 2，带正确大纲级别 |
| 正文 | 普通段落样式，保留空段落、段内换行和有意义空白 |
| 分页 | 目录后正文另起一页；每卷另起一页；章标题与紧随正文尽量同页 |
| 基础样式 | A4、常规页边距；正文默认宋体 12pt、1.5 倍行距，卷章标题层次清晰 |

正文不自动增加首行缩进或自动替换字符，避免与作者已有空格叠加。首版不嵌入字体，实际字体显示依赖阅读软件；不承诺与编辑器逐页相同。

### 6.2 目录行为

- 必须支持在 Word/WPS 导航窗格中识别卷、章层级；不能只靠字号模拟标题。
- 目录覆盖标题 1–2，包含空卷和空章，可点击跳转；重名标题也能跳转到各自位置。
- 导出文件内提供初始目录条目和有效的内部链接，首次打开即可使用，不应只出现一个空 TOC 域。
- 同时提供标准 TOC 域及打开时更新域的设置，方便作者在 Word/WPS 中更新整个目录和页码。
- 导出器不自行推测页码；初始条目可不带页码。页码由阅读软件排版和更新目录后生成。
- 软件不执行域更新时，初始目录仍可点击；格式弹窗的 DOCX 说明区域补充“目录页码可在 Word/WPS 中更新”。
- 没有卷章条目时保留书名、非空作者和简介，不生成空目录页。

验收需分别核对初始可点击目录、标题导航以及更新后的目录，不能仅以文件扩展名正确或 XML 含 TOC 字样判定支持目录。

## 7. 保存与快照一致性

### 7.1 导出时点

用户在系统保存对话框确认最终路径后，发起保存屏障。导出的内容定义为：**本次保存屏障完成后，数据库中同一份一致性快照包含的当前作品内容**。

- 保存屏障必须捕获编辑器最新状态，包括尚未到达自动保存延迟的正文、当前章标题和正在提交的目录重命名，以及已提交但尚未完成的作品信息保存。
- 等待当前作品已经启动的保存操作完成，包括切章前一章的后台保存；不能只保存此刻打开的章节。
- 如存在未结束的输入法组合输入，先结束并同步该次输入，再确认保存成功。
- 无编辑变更时跳过重复写入，仍须等待已有保存操作。
- 首页导出若没有挂载编辑器，不等待不存在的编辑器应答；有其他打开同一作品的编辑窗口时，须向相关窗口发出保存请求并等待完成，不能因入口在首页而跳过未保存内容。
- 任何保存失败、窗口无响应或等待超时都停止导出，提示“编辑内容未保存，未生成导出文件，请重试”；不能回退为旧数据库内容继续导出。

### 7.2 一致性流程

1. 记录请求 ID、当前作品 ID、格式及用户确认的目标路径。
2. 暂停当前作品的本地编辑与结构修改入口，刷新最新编辑器状态，将待保存内容提交到可等待的保存队列。
3. 等待当前作品所有相关保存和已启动的写入完成；失败时解除暂停并停止。
4. Main 在同一读取事务或等价的一致性读取机制中读取书名、作者、简介、编号配置、全部有效卷及完整章节正文，形成不可变快照。
5. 取得快照后解除编辑暂停，再转换和生成文件。后续手动编辑、同步或 Agent 写回仅影响下次导出。
6. 若期间作品被删除、应用切换数据集或开始恢复资料，停止或拒绝导出，不能读取一半旧库、一半新库。

读取快照应通过现有数据维护边界协调。不能在申请独占维护锁后再等待渲染层保存，否则保存本身可能被锁拒绝。避免在完整文件生成期间持有数据库事务或全局写锁。

并发同步与 Agent 写回必须完整地位于快照之前或之后，不能把单次事务中的部分变更混入文件。导出不主动触发云同步，也不等待模型生成或未应用草稿。

## 8. 实现落点建议

实现按以下边界组织：

| 层级 | 职责与落点 |
| --- | --- |
| 产品界面 | `apps/desktop/src/pages/Home.tsx`、`apps/desktop/src/pages/editor/EditorWorkspace.tsx`：两处按钮共用格式弹窗、进度和结果 |
| 编辑保存 | `apps/desktop/src/pages/editor/hooks/useChapterLifecycle.ts`：可等待的保存屏障、切章保存跟踪、失败向上传递 |
| IPC | `apps/desktop/electron/preload.ts`、`apps/desktop/src/vite-env.d.ts`：导出调用与进度事件的类型契约 |
| 主进程 | `apps/desktop/electron/main.ts`：注册导出入口、验证调用窗口与当前作品、协调保存和维护状态 |
| 桌面协调 | `apps/desktop/electron/services/NovelExportService.ts` 及 `apps/desktop/electron/agent/DocumentExporterClient.ts`：系统对话框、保存屏障、快照、公共转换适配、Python 进程调度、临时目录与最终提交 |
| 公共转换 | 复用并扩展 `apps/desktop/shared/lexicalDocument.ts`：同一套解析遍历提供可读文本及保留结构的段落结果，TXT / DOCX 共用；保留旧调用的默认语义 |
| Python 文件生成 | `agent_runtime/document_exporter/`：快照数据校验、作品信息排版、TXT 编码与换行、DOCX 标题/目录/书签、生成进度与临时产物 |
| 数据来源 | `packages/core/prisma/schema.prisma` 中的 Novel / Volume / Chapter；首版无需增加业务表或数据库迁移 |

实现对既有链路的处理：

- `saveChanges`、切章保存及目录重命名接入按作品保存队列；失败的保存保留待提交快照，导出重试时再次等待保存。队列跨编辑器卸载保留，首页导出也等待未完成写入。
- 导出使用独立 flush 请求、窗口应答和超时，不启动全量备份流程；备份 flush 同步复用增强后的编辑保存屏障。
- `db:get-volumes` 提供的是目录所需章节元数据，导出需要额外读取完整正文，不能假设侧栏数据包含全章内容。
- `extractReadableText` 是已有公共方法，会修剪空白、压缩空行，当前遍历没有专门输出 Mention 的 `mentionName`；在该公共模块内增加保留结构的输出能力，让原方法与导出共享底层遍历，避免另造解析器，也避免直接改变现有摘要、比较等调用的默认结果。
- `main.ts` 另有局部 `extractTextFromLexical`，会把空白压成空格，服务字数等用途；导出应走上述公共模块，不复制这个局部实现。
- `agent_runtime/pyproject.toml` 已声明 `python-docx`，优先复用 Python 依赖环境完成 DOCX 生成；目录域、书签和初始链接按本设计补齐，不依赖用户安装 Office 才能生成文件。

### 8.1 Python 优先的职责划分

后续新增或迁移的能力优先评估落在 Python 的公共 Service / Worker，减少 Electron 内领域逻辑。本次只落实导出链路，不以此启动整个项目迁移。

```text
首页 / 编辑页 → Electron 保存屏障与数据库快照
             → 复用公共 Lexical 转换，传递作品信息与段落数据
             → Python Document Exporter Worker 生成 TXT / DOCX 临时产物
             → Electron 校验结果并提交到用户确认的路径
```

- Python 是本次 TXT 和 DOCX 文件生成的执行方；Electron 保留 UI、系统对话框、数据库事务和最终用户文件提交职责，不在 TypeScript 再实现一套生成器。
- 为复用已有公共 Lexical 方法，首版在 Electron 调用公共转换后传递格式无关段落。该适配不承担 TXT 拼接或 DOCX 排版；未来如将 Lexical 转换迁到 Python，应作为公共能力统一迁移，并通过共享样本验证，避免长期维护两套规则。
- Worker 是按需启动、无模型、无状态的独立 Python 模块，不属于 LangGraph，也不要求启动 Agent 服务。可参考现有 `DocumentExtractorClient.ts` 和 `document_extractor` 的进程封装、UTF-8 协议与打包方式，不混用导入提取协议。
- 输入包含协议版本、请求 ID、格式、作品元数据、稳定卷章顺序和段落数据；大快照可通过受控临时文件传递。Python 只访问本任务输入和输出临时目录，不直接读取 Prisma/SQLite，不读取任意本机文件。
- 输出包含关联请求的进度、结构化成功结果或错误码；临时文件位于目标目录所在文件系统，最终路径由 Electron 持有。进程异常退出、协议错误和依赖不可用均失败退出，不静默切换到另一套 JS 导出。
- 开发环境及 Windows/macOS 发布包均需携带可用 Worker 和依赖；用户无需自行安装 Python。不能仅以开发机可运行作为导出功能完成标准。

导出结果契约区分 `success`、`cancelled`、`failed`，携带请求 ID；成功包含最终路径、实际卷章数、是否无正文、是否为目录及生成文件列表。进度事件关联请求，旧任务事件不能覆盖新任务状态。失败提供稳定错误码及可读原因，不将正文写入日志。

## 9. 文件写入与异常处理

- 先生成到目标目录内的唯一临时文件，完成写入和关闭后再提交至最终路径。重名覆盖采用同目录安全替换，不先删除原文件。
- 保存、读取、转换和写入任一阶段失败时，不留下被误认为成功的半成品，不破坏原目标文件；清理本任务临时文件。
- 无写权限、目录已消失、磁盘空间不足、文件被 Word/WPS 占用时说明原因，允许换位置重试。
- 重试必须重新执行保存屏障和快照，不能使用失败任务中的旧正文。
- 不自动打开文件；“打开所在文件夹”只操作实际成功的最终路径。
- 公共 Lexical 转换不在 React 渲染过程中进行，Python 子进程承担 TXT / DOCX 文件生成和临时产物 I/O。大作品逐章处理并报告进度，避免在内存中保留多份全书字符串；公共转换若明显阻塞 Main 事件循环，使用 Node Worker 调用同一公共模块，不复制解析逻辑。
- 若生成器或内存存在实际限制，预检后明确失败并解释原因，不能静默截断或漏章。

| 场景 | 用户结果 |
| --- | --- |
| 取消格式或保存对话框 | 正常返回，无成功或失败提示 |
| 当前内容保存失败 / 保存应答超时 | 停止导出，保留编辑内容，提示先完成保存后重试 |
| 作品不存在或已删除 | 停止导出，提示刷新或返回作品列表 |
| 正文不支持或结构损坏 | 停止导出，指出具体卷章，保留原内容 |
| 备份恢复 / 数据维护冲突 | 提示当前正在处理资料，结束后重试 |
| 路径或写入错误 | 停止提交，保留原目标文件，可重选位置 |
| Python Worker 缺失、启动失败或异常退出 | 停止导出，提示生成服务不可用或生成失败，清理临时产物，可重试 |
| 空作品或全空章 | 正常导出实际标题结构，提示无正文内容 |

## 10. 验收标准

以下用例定义完成标准；已执行项目及未覆盖环境详见[首版验收记录](./novel-export-acceptance.md)。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| E01 | 当前作品有多卷、多章，创建和修改时间与目录顺序不同 | 两种格式均按卷、章 `order` 排列，所有正文完整，未混入其他作品 |
| E02 | 最后一次输入后立即导出，未等自动保存 | 文件包含最后一次正文和标题修改，含中文输入法最终提交文字 |
| E03 | 修改 A 章后立即切到 B 章并导出 | 等待 A、B 相关保存，文件不遗漏 A 章修改 |
| E04 | 队列中任一保存失败或保存应答超时 | 导出停止，无成功文件；编辑仍在，可重试 |
| E05 | 侧栏折叠、没有当前章、只有部分章进入过缓存 | 仍读取全部有效章节正文 |
| E06 | 空作品、空卷、空章、软删除卷章 | 空结构按规则保留，软删除内容排除，全空时有说明 |
| E07 | 自定义编号、空标题、重名标题、重复 `order`、标题自带相同编号 | 编号符合规则且无重复前缀；顺序稳定；不去重记录 |
| E08 | Lexical 文本、Mention、标记包裹文字、空段、段内换行、Emoji、缩进 | 两种格式的正文文字与段落语义一致，无节点 JSON、ID 或漏字 |
| E09 | 历史纯文本、以花括号开头的纯文本、合法空 JSON 文档、确认损坏的结构化正文 | 正确识别空内容和历史内容；损坏时定位失败，无静默空章 |
| E10 | TXT 在常见 Windows 文本编辑器中打开 | UTF-8 中文正常，CRLF、标题分隔、正文空行和缩进符合规范 |
| E11 | DOCX 用 Word 与 WPS 分别打开 | 无修复提示；标题导航正确；初始目录可点击，重名条目定位正确 |
| E12 | 在 Word/WPS 更新整个目录 | 卷章层级、跳转和更新后的页码正确，书名、作者、简介与目录标签不进入卷章目录 |
| E13 | 两种格式互相比对 | 排除结构分隔、目录及编码差异后，每章正文文字和顺序一致 |
| E14 | 取消、覆盖拒绝、无扩展名、错误扩展名、非法书名字符 | 取消无文件；最终格式与扩展名一致；覆盖确认针对最终路径 |
| E15 | 无写权限、磁盘写满、目标被占用、生成异常 | 不破坏旧文件、不留下最终半成品、退出忙碌状态，可换路径重试 |
| E16 | 保存对话框停留期间继续编辑，快照后继续写作或发生同步写回 | 确认导出前的编辑已保存；快照后变更不混入同一次文件 |
| E17 | 连点导出、切模式、备份恢复冲突 | 无重复任务或跨作品结果；维护冲突可理解且可恢复 |
| E18 | 大作品：至少 100 万正文字符、1,000 章、多个卷 | 不漏章、不截断，进度可见且界面可响应；记录耗时、峰值内存及测试设备 |
| E19 | 作者及多段简介非空 / 为空，导出前更新作品信息 | 非空时在正文前完整输出，TXT / DOCX 顺序一致；空项无占位；使用同一快照中的最新已保存信息 |
| E20 | 首页直接导出、编辑页写作 / Agent 模式导出 | 两处入口使用同一流程；锁定所选作品；无编辑器时不等待虚假应答，有同作品编辑窗口时完成保存 |
| E21 | Windows/macOS 发布包在没有系统 Python 的环境导出；模拟 Worker 异常退出 | 两种格式由随包 Python Worker 生成；异常无最终半成品、无静默 JS 回退，可恢复操作 |
| E22 | 公共转换旧调用与导出路径回归 | 导出复用公共遍历并保留段落；原有可读文本提取、内容比较、摘要等行为不因新增导出模式意外变化 |
| E23 | 指定范围跨卷，显示章号重复、范围越界或输入非整数 | 使用全书目录位置，保留原标题和编号，无重复或遗漏；无效范围拒绝导出，不改目标文件 |
| E24 | 每 500 章自动拆分，末份不足 500 章 | 文件名、范围和进度正确；每份有独立作品信息及目录；全集按顺序覆盖全部章节一次 |
| E25 | 第二份及以后生成失败或分批期间继续编辑 | 不留下最终半套文件；重试创建新快照，正常分批均使用同一次快照 |

验证按三层开展：转换和排序的确定性用例、真实数据库保存屏障与文件落盘集成验证、桌面端和 Word/WPS 人工验收。无需为本次纯文档修改运行应用构建；后续功能交付必须附实际验收结果及未覆盖环境。
